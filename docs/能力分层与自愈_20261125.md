# 能力分层与自愈：让 4B 也能"写代码、做项目"，同时守住老机器

> 2026-11-25 · 设计稿 + 本轮落地记录
> 一句话：**不是把 4B 变强，而是让不同的活走不同的路，让每一步都有人兜底。**

---

## 一、目标拆成四件事

| 想要 | 真正的难点 | 走哪条路 |
|---|---|---|
| 能写代码、做项目设计 | 4B 的规划/代码能力天花板，靠提示词补不回来 | **设计档**：接口模型（DeepSeek）出计划/代码，本地模型只负责执行和验证 |
| 能在老机器上跑 | 内存 8 GB、无显卡、上下文 6144 | **执行档**：4B + 技能 + 场景模板，永远不要求它"想" |
| 首次体验不能像个卡死的软件 | 冷启动 prefill 4900 tok ≈ 130 秒 | 预热进度可见 + 冷启动任务走接口 / 预热按 flow 分档 |
| 多步任务别一头撞死 | 4B 会在同一步反复试、然后交出半截答案 | **三层自愈**：换方法 → 换工具 → 升级模型/降级交付 |

---

## 二、三档能力，一套工具

同一个 harness、同一套 65 个工具、同一套验收，只是**谁来想**不同：

| 档 | 模型 | 适合 | 上下文预算（大致） |
|---|---|---|---|
| 执行档 | 本地 4B | 具体操作、场景模板、已给明确步骤 | system 1.5k + tools 1.5k + 历史 1k + 任务 0.5k |
| 设计档 | 接口 | 写脚本、改项目、出方案、长文档 | system 2k + tools 2k + 历史 3k + 任务 2k（apiContext 64k 足够） |
| 混合档 | 接口出计划 + 本地执行 | 多步但每一步都很机械（整理/归档/巡检） | 计划占 0.5k，其余同执行档 |

**关键约束：三档必须共用同一套工具 schema 和同一个验收口径**，否则"接口写的代码本地跑不通"会变成新的坑。

### 分诊（route）怎么判

不调模型，纯规则打分，保证 0 成本、可解释：

1. 产物是程序（`.ps1/.bat`、"写个/做个/实现/支持"）→ **设计档**
2. 步骤估计 ≥6（任务里出现"然后/再/最后/并且"多次、多个文件路径）→ **设计档**
3. 命中场景包 / 单步操作 → **执行档**
4. 其余 → 执行档，但**第一次失败后允许升级**（见自愈 L3）

判定结果要写在面板和日志里（`[路由] 本地 / 接口，因为：产物是程序`），让人能质疑、能改配置。

## 三、三层自愈（本轮已落地 L1）

| 层 | 触发 | 动作 | 状态 |
|---|---|---|---|
| L1 换方法 | 同一工具 + 同一目标第 3 次 | 先不认输：把"已试过的 3 个动作"列给它，要求换一条路（run_cmd 一条命令 / 先读再改），并写进经验库 `source=self-heal` | **已落地** |
| L2 换工具 | 同一目标失败 2 次 | 按场景 cheatsheet 换等价工具（write_file → file_editor / run_ps），或缩小范围（只处理 1 个文件验证） | 下一步 |
| L3 升级/降级 | 连续 2 步没有任何新观察 | 有 key：把当前步之前的历史 + 观察打包给接口模型，让它给"下一步做什么"；没 key：降级为"最小可用一步"，先交出能验证的部分并说明没做完 | 下一步 |

原则：**永远不要用"半截观察"当最终答案**。L1 之后的收尾必须写明"卡在哪、试过什么"。

## 四、场景包（本轮已落地 3 个）

场景 = 预写好的步骤模板 + 工具白名单 + 禁止项，命中后直接跳过"想流程"，模型只填参数。

| id | 触发（举例） | 干什么 | 护栏 |
|---|---|---|---|
| `tidy_desktop` | 整理桌面 / 桌面太乱 / 收拾桌面 | 按类型建目录并 `move_path` | 只挪不删、不覆盖同名 |
| `tidy_downloads` | 把下载目录 / 归档下载 | 按年月归档 | 安装包/进行中的下载可留下 |
| `clean_temp` | 清理临时文件 / 垃圾文件 | 先列清单和大小，明确要删才删 | 不碰系统目录；没让删就不删 |

已验证分流（本地测试，不跑模型）：整理桌面→`tidy_desktop`、下载归档→`tidy_downloads`、清理临时→`clean_temp`；
"看看桌面文件有哪些"仍然不命中（只读问题不该触发挪文件）。

**下一步**：面板输入框上方加一排"场景"按钮（一键填好参数），以及每个场景的"试跑"-"真跑"两档。

## 五、自己办公 / 管服务器 / 自动化

> 2026-11-25 决定：**服务器操作工具（svc / sched / remote_ps / ssh_exec）先不做**，
> 接口模型也先不接（key 留着需要时自己填）。本轮只做"定时 + 健康触发"的调度器，
> 文件变化触发因为误报太多，明确推迟。

这三件事不是"再加几个工具"能解决的，需要三样东西：

### 1. 服务器操作工具（还缺）

| 工具 | 干什么 | 依赖 | 护栏 |
|---|---|---|---|
| `svc` | 查/启/停 Windows 服务 | 本机 | 只允许白名单服务，停服务要二次确认 |
| `sched` | 计划任务（schtasks）查/建/删 | 本机 | 只动 Nafx 自己的任务名前缀 |
| `remote_ps` | WinRM 远程跑 PowerShell | 目标开 WinRM | 目标白名单 + 只读默认 |
| `ssh_exec` | SSH 跑一条命令 | 系统 OpenSSH | 主机白名单 + 命令模板，不允许交互式 |
| `health` | 端口/磁盘/关键日志一次性体检 | 本机或远程 | 只读 |

### 2. 调度器（还缺）

`jobs.json`：一条自动化 = 触发 + 任务 + 护栏。

```json
{ "id": "night-clean", "when": "daily 02:30", "task": "清理一下临时文件",
  "scope": "workspace/tmp", "dryRun": true, "notify": true }
```

- 触发类型：定时（cron-ish）、文件变化（目录新增）、健康检查失败（8090 不通 → 落一条故障任务）
- 执行者：`scripts/watchdog.ps1` 里加一个 tick，不新开进程
- 面板加"自动化"抽屉：启停、看最近 20 次结果、手动跑一次

### 3. 审计与护栏

- 所有自动化任务写 `Agent monitor.log`（类型 任务/完成/故障），与手动任务同一个口径；
- 危险动作（删除、停服务、远程执行）默认 `dryRun`，要"真跑"必须面板勾选一次；
- 目标白名单放 `config.json`（`autoTargets`），不在白名单的路径/主机直接拒绝。

## 六、里程碑与验收

| 阶段 | 交付 | 验收指标 |
|---|---|---|
| M1（本轮） | 预热进度可见、L1 自愈、3 个场景包 | 预热有"还剩 N 秒"；重复第 3 次不再直接交半截答案；3 个场景分流正确 |
| M2 | 路由（执行/设计/混合）+ 冷启动走接口 | 写代码类任务自动进设计档；冷启动首任务 ≤ 20 秒（有 key） |
| M3 | L2/L3 自愈 + 经验回写 | 7 步以上任务失败率减半；失败答案里必须写卡点 |
| M4 | 服务器工具 + 调度器 + 自动化抽屉 | 一条"每天凌晨清理 + 周一巡检"能跑一周不误报 |
| M5 | 场景面板化 + 参数表单 | 常用 6 个场景 0 输入启动 |

**不做的事**：不追工具数量、不做多路并行（CPU 上并行只会更慢）、不为了"通用"牺牲可解释性。

## 七、已知风险

1. **接口模式的数据出门**：设计档会把任务内容和文件片段发到服务商，敏感目录要配置排除。
2. **分诊误判**：规则打分会把"整理一下桌面然后写个脚本"判成设计档——允许手动覆盖（面板胶囊点一下固定档位）。
3. **自愈烧步数**：L1/L2 都会多花 1–2 步；步数上限 25，长任务要盯 `[自愈]` 日志，必要时把 L2 关掉。
4. **调度器误触发**：文件变化触发必须做去抖（同一文件 60 秒内只触发一次），否则一次解压能触发上百个任务。

## 八、2026-11-25 落地记录：定时 + 健康触发

已实现（`scripts/scheduler.ps1` + `jobs.json` + 看门狗 tick + 面板「自动化」抽屉）：

- `daily HH:MM` / `every Nm` / `health`（probe = disk / model / panel，带 failAfter 与 cooldown）；
- 每 60 秒 tick 一次，不新开进程；面板活着进队列（priority 8），面板死了直接拉 `agent.ps1`；
- 有任务在跑就等下一轮；任务一律 `auto` 模式；
- 结果从 `history.jsonl` 回收；45 分钟没结果标 `lost`（中断），不会永远显示「已排队」；
- `logs/jobs.log` 记每次触发与回收，面板抽屉显示最近 16 行。

**真实验证**：`daily-disk-report` 手动触发 → 队列 `q173934c76d` → 168 秒完成：
"C 盘剩余 13.7 GB，D 盘 61.1 GB，E 盘 17.3 GB。E 盘最紧张。logs 目录大小未直接查询…"（数字全对，没编）。
健康触发用 mock 提交验证：阈值 99 GB 时第 1 次不触发、第 2 次触发、第 3 次进冷却。

**踩到的四个坑（都已修，别再犯）**：

1. **中文任务变问号**：`Invoke-RestMethod -Body <字符串>` 在 PS 5.1 会按本地代码页编码，
   到面板变成 `??????`，模型只能瞎猜。必须 `[Text.Encoding]::UTF8.GetBytes($body)`。
2. **面板自己请求自己会死锁**：HttpListener 单线程，`/api/jobs` 里回调 `/api/run` 会把整个面板卡住
   （所有 API 一起超时）。面板内部一律直接调 `Add-QueueItem`。
3. **读追加中的文件会卡死面板**：`Get-Content -Tail` 遇到写句柄会等，单线程面板直接全站卡住。
   改用 `FileStream + FileShare.ReadWrite` 读全文再取尾部。
4. **自动加"只读"前缀会把 4B 带偏**：加 40 字前缀后，"2 加 2 等于几"跑了 7 步去 `find_files` 找 `*.zip`。
   `readonly` 现在只是标记，约束写进任务文字本身。

**变量命名**：调度器的脚本级变量全部 `Nafx` 前缀——`$script:StateFile` 曾和 monitor 自己的
`agent\state.json` 撞名，导致面板读到空状态、甚至可能把 agent 状态覆盖掉。

**下一步（等确认）**：场景面板化（一键场景 + 参数表单）；服务器工具与 SSH 凭据方案（本轮明确不做）。
