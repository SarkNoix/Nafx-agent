## 它和别的 agent 框架差在哪

我翻过 [188 个开源 agent harness](https://github.com/RyanAlberts/best-of-Agent-Harnesses)，
绝大多数要 Python、Node 或者 Docker。

Nafx 只用 **Windows 自带的 PowerShell**——不用装 Python，不用装 Node，不用装 Docker，
下载、解压、双击。

| | 大多数 agent 框架 | Nafx |
|---|---|---|
| 运行环境 | Python / Node / Docker | **系统自带 PowerShell** |
| 装依赖 | pip / npm | **不用装** |
| 内存 | 16 GB 起 | **8 GB 能跑** |
| 界面 | 英文 CLI | **中文面板** |
| 启动 | 敲命令 | **双击 bat** |

这个组合在我翻过的 188 个里没找到第二个。

**为什么走这条路**：不是"不想用 Python"，是**目标机器装不了**。
办公室淘汰的四核老机器、家里人用的笔记本——它们没有开发环境，
但一样需要一个能整理文件、算表格的助手。

## 这是什么

Nafx 是一个跑在你自己电脑上的 AI 助手。你说话，它动手——读写文件、跑命令、处理表格、整理目录。

它有这些特点：

- **完全本地**：模型跑在你电脑上，数据不出门
- **不用显卡**：CPU 就能跑，核显机器也行
- **默认不花钱**：本地模型没有 API、没有订阅；想快可以切 DeepSeek 接口，按 token 计费，面板里能看到累计花费
- **能真干活**：29 个预设技能 + 65 个工具，常见活儿一句话搞定
- **可扩展**：加一个 `.ps1` 文件就是一个新技能
- **Windows 原生**：纯 PowerShell，不装 Python，不装 Node
- **看得到过程**：面板上每一步在想什么、做了什么、返回什么，以及累计用了多少 token

## 它是怎么工作的

大部分人对 AI 助手的想象是"一个无所不能的大脑"。

**不是的。**

Nafx 的核心想法是：**模型只管判断，干活交给技能。**

```
你说："帮我找出这个文件夹里重复的文件"

模型做的：判断这活儿该用哪个技能   →  find_duplicates
技能做的：真正的活（算哈希、分组） →  直接出结果
```

模型不需要会写代码，只需要会**选**。选是它擅长的，写代码不是。

这就是为什么一个 4B 的小模型能干出像样的活。

### 为什么不直接让模型写代码

试过。它会：

- 写出来的逻辑有 bug（用哈希当键存文件名，同哈希的互相覆盖）
- 发现不了自己的 bug（输出"没找到重复"也照单全收）
- 或者干脆放弃计划，改成一个个手动读文件

这不是提示词能修的，是模型规模的问题。

**换个思路**：把"怎么干"提前写成验证过的脚本，模型只负责挑。

结果：

| | 让模型自己写 | 用技能库 |
|---|---|---|
| 找重复文件 | 700 秒，超时，结果错 | 204 秒，结果对 |

### 2. 双击启动

```
Nafx.bat
```

它会：

1. 启动模型服务（第一次要等几十秒加载）
2. 开一个 `Agent monitor` 窗口（事件记录器，只记录、不参与干活，可随时关掉）
3. 启动面板
4. 自动打开浏览器

面板地址：`http://127.0.0.1:8090`

**启动后模型会先自己预热**：把上一次任务的请求体原样重放一遍（日志在 `logs/warmup.log`），
让提示词和工具前缀先算进 llama 的缓存，这样第一个任务的首字能快很多。
预热期间面板顶栏会显示「预热中 · 还剩约 N 秒」，不会让你看着像卡死。
不想让它开机就占 CPU，把 `config.json` 的 `warmupOnStart` 改成 `false`。

## 两套配置

仓库里有两个配置文件：

| 文件 | 怎么启动 | 用途 |
|---|---|---|
| `config.json` | 双击 `Nafx.bat` | 默认，开箱即用，按保守假设写 |
| `config.self.json` | 双击 `Nafx 我的配置.bat` | 个人配置**模板**，默认值与 `config.json` 对齐，只放宽单条命令超时和输出上限 |

**为什么不合并成一个**：默认配置要照顾别人的机器（内存未知、权限保守）。个人配置留给你按自己的机器放开，
模板里只预置了两个安全项——单条命令 45 秒（默认 30）、一次工具输出 1200 字符（默认 800），其余保持默认。

**`config.self.json` 里能改什么**：

```json
{
  "runTimeoutSeconds": 45,  // 默认 30，长命令（findstr / robocopy）不容易被截断
  "maxOutputChars": 1200,   // 默认 800，一次多看些输出
  "temperature": 0.25,      // 默认 0.3，更低更稳
  "allowAdmin": false,      // 默认 false。要开就在面板里临时提权，别写死在配置里
  "personalPrompt": ""      // ← 这个最有意思，下面说
}
```

**`personalPrompt` 是什么**：

一段话，会追加到系统提示词末尾。写你自己的习惯，模型每次都知道。模板里留空，填了才生效；
里面写相对路径（如 `workspace`），不要写本机绝对路径——这份文件是公开仓库的一部分：

```json
"personalPrompt": "回答用中文。拿不准的时候先问，别猜。\n常用工作区：workspace。"
```

运行时日志里会显示 `带上个人指令（xx 字符）`，能确认生效了。

**换配置启动的原理**：`launcher.ps1` 和 `monitor.ps1` 都支持 `-ConfigFile` 参数，`agent.ps1` 从环境变量 `NAFX_CONFIG` 读。想加第三套配置，复制一份改个名字就行。

## 换电脑了怎么办

Nafx 的参数是按机器算的，换台电脑直接跑可能不合适（内存小的会被换页拖死，内存大的又浪费）。

**双击 `自动调参.bat`**，它会：

```
1. 读你的 CPU 核数、内存大小、显卡、llama.cpp 是不是 CUDA 版
2. 算出这台机器最合适的参数
3. 和当前配置对比，告诉你差在哪
```

输出长这样：

```
CPU     Intel Core i3-10105F
        4 物理核 / 8 逻辑核
内存    7.85 GB（当前可用 1.13 GB）
显卡    NVIDIA GeForce GT 730（2 GB）
推理版  CPU 版（显卡用不上）

推荐值 vs 当前值
context                5120      5120   按内存和模型大小算
threads                   0 →       4   物理核数
maxTokens               500 →     600   核多给多点
maxSteps                 30 →      25   内存紧就少给
stepTimeoutSeconds      180 →     240   核少的机器超时给够
```

**双击 `自动调参并应用.bat`** 会先备份成 `config.json.bak`，再写进去。

**推荐值是怎么算的**：

```powershell
# 留给系统的：Windows + 浏览器 + agent，实测约 2.5 GB
# 安全余量：512 MB（吃满内存反而更慢）
# 每 token 的 KV cache：4B Q4 实测约 0.4 MB，按模型大小缩放

context = (总内存 - 2.5 - 模型大小 - 0.5) * 1024 / 每token内存
```

这套公式在 8 GB / 16 GB / 32 GB 上都对过，8 GB 跑 4B 算出来正好是 6144——和实测能吃住的值一致。

### 面板里也能改

右上角「设置」→ 往上滚到「运行参数」，几个数字直接改，保存就行。

**有范围校验**：context 不能超过 32768、threads 不能超过 32、超时不能低于 30 秒。填错了会被拒绝并告诉你正确范围。

改完要重启服务（抽屉里会标出哪些项要重启，需要就点「重启服务」）。

## 配置

全在 `config.json` 里，每一个都有中文说明。改完重启服务生效。

最常改的几个：

```json
"model":       "models/xxx.gguf",  // 模型路径
"modelMode":   "local",             // local = 本地 llama；api = DeepSeek 接口
"context":     6144,                // 上下文长度，越大记得越多但越慢（8GB 老机器用 自动调参.bat 会压到 5120 以下）
"maxTokens":   600,                 // 单步最多生成多少，太大会卡
"maxSteps":    25,                  // 一个任务最多几步
"threads":     0,                   // 0 = 自动按核心数
"warmupOnStart": true,              // 启动后在后台预热（重放上次的请求体）
```

接口模式还有几个：

```json
"apiBase":          "https://api.deepseek.com/v1",
"apiModel":         "deepseek-chat",
"apiContext":       64000,          // 接口上下文上限，别超过服务商给的
"apiPriceIn":       2.0,            // 元 / 百万 token：未命中缓存
"apiPriceCacheHit": 0.2,            // 元 / 百万 token：命中缓存
"apiPriceOut":      3.0,            // 元 / 百万 token：输出
```

`apiPrice*` 只影响面板里「累计花费」的估算，改价就改这三个数。key 在 `api-key.json`，不进 git。

## 技能库

`skills/` 里每个 `.ps1` 就是一个技能，`skill.json` 是索引。

现在有 29 个：

**文件** 找重复文件、按扩展名统计、找大文件、批量改名、比较文件、目录树、合并文件、重复行去重、清理空目录、按日期归档、批量解压、压缩成 zip

**文本** 文本统计、搜关键词、批量替换、日志提错误

**表格** CSV 统计、查某人某项、字段求和、CSV↔jsonl、Excel 转 CSV

**数据** 查 JSON / JSONL 字段，数字自动求和、平均、最大最小

**网页 / 网络** 抓网页正文、发 HTTP 请求看响应（`http_probe`）、测端口（`port_check`）、查 DNS（`dns_lookup`）

### 加一个自己的技能

**1. 写个脚本** `skills/我的技能.ps1`

```powershell
param([string]$Path = '.')

# 干活
$files = Get-ChildItem $Path -File
Write-Output ("这里有 " + $files.Count + " 个文件")
```

**2. 在 `skills/skill.json` 里加一条**

```json
{
  "name": "my_skill",
  "title": "我的技能",
  "desc": "这个技能干什么",
  "triggers": ["触发词1", "触发词2"],
  "params": "-Path <目录>",
  "example": "skill(command=\"my_skill -Path test\")"
}
```

**3. 完事**

模型 `skill(command="list")` 就能看到它，中文名字也能匹配上。

**技能怎么写才好**：

- 开头写清楚这脚本干什么、怎么用
- 用 `param()` 声明参数，给默认值
- 出错时输出人能看懂的话，别直接抛异常
- **破坏性操作默认只预览**，加 `-Apply` 才真动手

## 面板

浏览器打开 `http://127.0.0.1:8090`。面板就是 `agent/dashboard.html` 一个文件，数据走 `/api/state`（运行中约 350 毫秒刷一次）。

**顶栏从左到右**：`Nafx`（点它有彩蛋）· 模型名 · 模型来源胶囊（`本地 llama` ↔ `DeepSeek 接口`，点一下切）· 意图 · 步骤 · 用时 · 累计用量胶囊。
最右边是五套主题和 `模型 / 队列 / 历史 / 设置` 四个抽屉。

![累计用量明细](images/panel-usage.jpg)

**累计用量胶囊** —— 形如 `Σ 总用量 132.9k tok · 缓存 79% · ↗ 输出 49.5k`：

- 数字是**总量**，不是这一次请求的量。agent 每发一次请求就把输入 / 输出 / 缓存命中的 token 累加进
  `agent/logs/usage.json`，跨任务、重启都不清零。
- 输入 = 新算的 + 缓存命中的（llama 的 `prompt_n` 只是这次新算的那部分，单用会把总量算小）。
- 接口模式下第三格自动变成 `¥花费`，按 `config.json` 里的单价估算
  （`apiPriceIn` / `apiPriceCacheHit` / `apiPriceOut`，单位是元 / 百万 token，默认 DeepSeek 官方价）。
- 点开明细：累计请求数、累计输入、其中缓存命中、累计输出、累计总计、累计花费；
  下面再分一段「本次请求」，写这一次的命中 / 新算 / 生成 / 速度 / 上下文。

### 侧栏

**自主模式** —— 选「干 10 / 30 / 60 / 120 分钟」，点「让它自己干」，它就不问你自己拍板干活；
派出来的任务标题带 `[自主]` 前缀。可以填一个方向（比如「整理桌面」），不填就自己找事做。

**配置** —— 2 列小卡片，模型名占整行：

```
┌──────────────────────────┐
│ 模型   Qwen3-4B-…         │  ← 占整行
├─────────────┬────────────┤
│ 上下文       │ 每路容量    │
│ 6144        │ 6144 tok   │
├─────────────┼────────────┤
│ 工具数       │ 最多步数    │
│ 65 个       │ 25         │
├──────────────────────────┤
│ 权限   管理员              │
└──────────────────────────┘
```

**上下文占用** —— 顶部一根四段总条，一眼看出挤不挤：

```
已用                    3.3k / 5.4k tok
[███████░░░░░░░░░░░░░░░░░░░░░░░]
 提示词   对话   工具   剩余      ← 图例
```

标题右侧有百分比，**≥65% 变黄、≥85% 变红**；下面三行细分（提示词 / 对话历史 / 工具定义）加一行「剩余可用」。

**工具 token 的口径要注意**：任务没跑起来时这几栏是「等任务开始后算」；
跑起来显示的才是**实际发出去的量**（按流程/意图裁剪后 12–16 个工具，约 1.5k tok）。
65 个工具的 schema 全量约 11.8k tok——发不起，会直接撑爆 6144 的上下文，所以才有「按流程/意图裁剪」这一步。

**工作区** —— 文件列表，点文件名可以在面板里打开。

**工具** —— 65 个按 9 组分类（文件/执行/系统/网络/数据/查询/流程/技能/版本），
顶上有个**搜索框**，按名字或描述过滤。点一下复制工具名。

**底部按钮** —— 2×2 排布：

```
[新对话]      [暂停对话]
[清除对话]    [管理员权限]
```

- 新对话：开一个干净的会话
- 暂停对话：立刻停掉正在跑的 agent，队列里那条标成暂停
- 清除对话：历史保留，但模型忘掉前文
- 管理员权限：弹一次 UAC，面板以管理员身份重启（就算配置里 `allowAdmin` 关着，也能临时开）

### 生成进度条

任务跑起来后，输入框上方会出现一条：

```
正在等模型首字…      3.7 tok/s · 缓存命中 98% · 上下文 61%
```

点开还能看到一个「模型正在写什么」的实时窗口：工具调用的 JSON 一个字一个字往外写，不做美化——
出问题（JSON 写歪了、参数不对）时直接从这儿就能看出来。

每条回答下面还有一个气泡胶囊，记着这一步的真实数据：`↯ 3.7 tok/s · ⧉ 缓存 98% · ▭ 上下文 3288/5364 61% · Σ 16 tok`。

### 设置抽屉

## 两种模型来源：本地 llama / DeepSeek 接口

顶栏那个胶囊点一下就切，配置里对应 `modelMode`：

| | 本地 llama | DeepSeek 接口 |
|---|---|---|
| 位置 | 自己的电脑 | DeepSeek 服务器 |
| 速度 | 4B 模型约 3.7 tok/s，首字等几十秒 | 快得多，首字基本秒回 |
| 花钱 | 0 | 按 token 计费 |
| 数据 | 不出门 | 任务内容会发到服务商 |
| 上下文 | 6144（按内存算） | 64000（`apiContext`，别超过服务商上限） |

**切到接口模式**：确认 `api-key.json` 里填了 key（去 <https://platform.deepseek.com/api_keys> 建一个，只改 `apiKey` 那行），
然后在顶栏点胶囊，或者在设置里把「模型来源」改成 `api`。**正在跑的任务不受影响，下次发任务才生效。**

**花费怎么算**：agent 用服务商返回的 `usage`（`prompt_tokens` / `completion_tokens` / `prompt_cache_hit_tokens`）累加，
再按 `config.json` 里的三个单价折算，显示在顶栏和累计明细里。单价变了就改这三个数，不用改代码。

换别家（阿里百炼 / 智谱 / 自建中转）也一样：key 放 `api-key.json`，地址和模型名改 `apiBase` / `apiModel`。

## 事件记录器（Agent monitor）

双击 `Nafx.bat` 会额外开一个控制台窗口，跑根目录的 `Agent monitor.ps1`。它是**记录**，不是仪表盘：
只把「什么时候、谁、发生了什么」追加进 `logs/Agent monitor.log`，一行一条，格式固定：

```
[2026-11-25 15:48:18][状态　][Agent monitor ]面板=在线，PID 11560，模型=Qwen3-4B-Instruct-2507（local）正常，
                                             llama=PID 8784
```

- 类型只有 11 种：任务 / 模型 / 工具 / 完成 / 故障 / 警告 / 生命周期 / 状态 / 信息 / 系统 / 错误
- 来源：面板 / watchdog / agent / llama / 模型 / Agent monitor
- **一个事件只记一条**。llama 一次请求两行（开始 + 结束），结束行写
  「输入 N tok，缓存命中 N，重算 N，等首字 N 秒，生成 N tok / N 秒（N tok/s）」
- 长信息按窗口当前宽度折行，**续行缩进对齐到信息列**——120 列窗口里不会再被看成一堆散落的孤立行
- 面板探活失败会先重试一次，连续两次失败才记「面板没有响应」；恢复只记一次；面板日志自己报了启动时不再重复记「面板重启」
- 记录文件超 5 MB 时，下次启动会先转存成 `Agent monitor.log.1`
- 按 Q 退出。参数：`-Once` 跑一遍就退、`-Replay` 只看各日志末尾 1 MB、`-Seconds N` 到点自己停（都是排查用）

数据源：`logs/panel/panel.log`、`logs/watchdog.log`、`logs/server.err.log`、`logs/warmup.log`、
`agent/logs/run_*.txt`、`agent/logs/history.jsonl`。

## 提速：预热 + 两级检索（2026-11-24 / 25）

- **预热**：第一步真正发出去的请求体存在 `agent/logs/last-request.json`，启动后在后台原样重放一遍（约 150 秒），
  把 system + 工具前缀先算进 llama 的 prompt cache。
- **同一会话里**，第二步之后的首字从 80 秒级降到 5 秒级（前缀命中缓存）；重启后的第一次请求仍要重新 prefill，所以才有预热。
- **精简 system**：每步请求前把 system 压到预算内，日志里那条 `[精简 system] 3182 → 1525 tok` 就是它。
- **两级检索**：历史和经验先按摘要粗排、再回读原文精排，只带真正相关的几条进上下文。
- **空转修复**：模型不按格式调工具、直接回一段 JSON 时，不再连续三次空转，而是识别出来、该收尾就收尾。
- 同一任务实测：**197 秒 → 56 秒**。设计细节在 `docs/上下文两级检索与提速_20261123.md`。

## 自动训练器（train/）

Nafx 带一个自测自改的工具：**自己出题、按步骤判分、发现短板后改提示词、再重考**。

目标是把分数刷到 95 以上。

```powershell
# 完整训练：刷到 95 分，最多 3 轮
powershell -ExecutionPolicy Bypass -File train\train.ps1 -Target 95 -Rounds 3

# 快速冒烟：每轮抽 60% 的题
powershell -ExecutionPolicy Bypass -File train\train.ps1 -Quick -Rounds 2

# 只考某一类
powershell -ExecutionPolicy Bypass -File train\train.ps1 -Category 联网

# 只看题目和评分规则，不调模型
powershell -ExecutionPolicy Bypass -File train\train.ps1 -DryRun
```

**跑之前先把模型服务起来**（双击 `Nafx.bat`，或者确认 8080 端口活着）。

**题库**在 `train/bank.json`（约 96 KB），分好几类：文件操作、数据统计、联网、系统查询。

**每轮会做什么**：

```
1. 出题 → 让 agent 真做一遍
2. 按预设的评分规则判分（数字对不对、文件改没改、有没有编答案）
3. 统计哪类题错得多
4. 改提示词 / 改流程模板
5. 再考一遍，看分数涨没涨
```

**输出**在 `train/out/`：每轮的备份、报告、调参日志。

这是把「感觉变好了」换成「分数涨了多少」的办法。

## 插件（mod）系统

一个 mod 就是一个 `.mod.json` 文件，扔进 `mod/` 目录，**不用改源码、不用重启模型**，agent 下次跑任务自动加载。删掉文件就是卸载。

### 它能改五样东西

```json
{
  "id": "coder-mode",
  "name": "程序员模式",
  "enabled": true,

  "config": { "temperature": 0.1, "maxSteps": 40 },
  "tools":  { "run_cmd": { "description": "跑命令前先说清楚要跑什么" } },
  "prompt": "改任何文件前先读清楚现有内容，不许凭印象改。",
  "docs":   [{ "name": "命名规范", "content": "变量用驼峰。" }],
  "script": "$env:MY_MODE = 'coder'"
}
```

| 字段 | 作用 | 生效时机 |
|---|---|---|
| `config` | 覆盖配置（温度、步数、个人习惯…） | 立即（`context`/`threads` 要重启模型） |
| `tools` | 禁用工具，或换掉工具说明 | 立即 |
| `prompt` | 追加人设/规则到系统提示词 | 立即 |
| `docs` | 追加 md 文档 | 立即 |
| `script` | PowerShell，加载时跑一次 | 立即 |

**改工具描述比想象中有用**——模型很依赖说明的措辞，换个说法就能改行为。

### 编辑器

三种打开方式，功能完全一样：

| 方式 | 说明 |
|---|---|
| 双击 `run-mod-editor.bat` | 起 8070 服务 + 自动开浏览器（推荐） |
| 双击 `mod-editor-standalone.html` | 不依赖服务，数据内联在页面里 |
| `http://127.0.0.1:8090/editor` | 借用面板的进程（面板在跑时） |

编辑器能改：基本信息、配置（26 项，分「立即生效 / 需重启」）、工具（65 个，9 组，可搜索/折叠/只看已改）、人设（带 4 个模板）、文档（可增删排序）、加载脚本（带语法检查）。

改完点「下载 mod 文件」，把下载到的 `xxx.mod.json` 放进 `mod/` 就生效。

右上角有 **预估 +N token**——mod 的 prompt 和 docs 都会进提示词，超过 600 要留意，超过 1200 会挤占正常任务的上下文。

### 技术细节

- **加载器**：`agent/mods.ps1`，agent 启动时调 `Get-Mods` / `Apply-ModConfig` / `Apply-ModTools` / `Get-ModPrompt` / `Invoke-ModScripts`
- **多个 mod 叠加**：按文件名排序，后面的覆盖前面的；人设和文档是全叠加
- **8070 服务**：`mod-editor-server.py`（Python，主）/ `mod-editor.ps1`（PowerShell，备用）
- **为什么主用 Python**：PowerShell 进程在没有控制台时，`Write-Host` 配合 `$ErrorActionPreference='Stop'` 会静默退出——实测 `Start-Process` / `start /b` 起的进程连脚本第一行都跑不到。Python 没这毛病，而且只占 30 MB

### 自带两个例子（默认停用）

```
mod/coder-mode.mod.json   程序员模式：温度 0.1、40 步、改前必须先读
mod/brief-mode.mod.json   极简模式：回答一句话，200 token 封顶
```

详细说明看 `mod/README.md`。

## 场景包与自愈（2026-11-25 起）

**场景包**是"预写好的流程"，命中后模型不再自己规划，只填参数。现在有三条：

| 说什么 | 走哪条流程 | 护栏 |
|---|---|---|
| 整理桌面 / 桌面太乱 / 收拾桌面 | `tidy_desktop`：按类型建目录再挪 | 只挪不删、不覆盖同名 |
| 把下载目录归档 / 归档下载 | `tidy_downloads`：按年月归档 | 安装包、进行中的下载可以留下 |
| 清理临时文件 / 垃圾文件 | `clean_temp`：先列清单和大小，明确要删才删 | 不碰系统目录 |

"看看桌面文件有哪些"这类只读问题不会命中（不然会去挪文件）。

**L1 自愈**：同一个工具对同一个目标试到第 3 次，不再直接拿半截结果交差——
先把"已经试过哪三次"列给它，要求换一条路（改用 `run_cmd` 一条命令、或先读再改），
并把这条教训写进经验库（`source=self-heal`）；换完还不行才收尾，而且答案里要写卡在哪。

分诊路由、L2/L3 自愈、服务器操作工具（svc / sched / remote_ps / ssh_exec / health）、
自动化调度器（`jobs.json` + 定时/文件变化/健康触发）的设计和里程碑在
[`docs/能力分层与自愈_20261125.md`](docs/能力分层与自愈_20261125.md)。

## 自动化：定时 + 健康触发

自动化写在项目根的 `jobs.json`，改完不用重启面板，下一轮就生效（看门狗每 60 秒 tick 一次，
不新开常驻进程）。

```json
{
  "id": "daily-disk-report",
  "name": "每天体检：磁盘 + 日志目录",
  "enabled": true,
  "when": "daily 02:40",
  "mode": "auto",
  "priority": 8,
  "readonly": true,
  "task": "看一下 C 盘和 E 盘各自还剩多少空间，说清楚哪个盘最紧张"
}
```

**三种触发方式**：

| 写法 | 含义 |
|---|---|
| `daily 02:40` | 每天到这个点跑一次；机器关了就在开机后补一次（不补第二遍） |
| `every 30m` | 每 30 分钟（最少 5 分钟） |
| `health` | 探针失败才跑：`probe: disk / model / panel`，`below` 是磁盘阈值（GB），`failAfter` 连续失败几次触发，`cooldownMin` 触发后多久不重复 |

**几条刻意的设计**：

- 自动化任务一律 `mode=auto`（无人值守，不许提问）、`priority=8`，**手动任务永远排在前面**；
- 有任务在跑就等下一轮，不插队——8 GB 机器同时跑两个任务是自杀；
- 面板活着就走队列；面板死了就直接拉 `agent.ps1`，"面板挂了"这类任务才不会永远跑不起来；
- 每次触发写 `logs/jobs.log`，最近结果从 `history.jsonl` 回收；提交后 45 分钟没结果标成「中断」，
  不会一直显示「已排队」；
- `readonly: true` **只是面板上的标记**，不会自动往任务前面加"只读"前缀——实测加了前缀反而把 4B
  带偏（"2 加 2 等于几"会跑去 `find_files` 找 zip）。真正的只读约束写在任务文字里。

面板顶栏的「自动化」抽屉可以看每个任务的上次结果、启用/停用、手动「跑一次」。

**暂不做文件变化触发**：一次解压能触发上百个任务，先去抖，等真需要再上（误报比漏报贵得多）。

## 实测性能（i3-10105F / 8 GB / 无显卡）

下面这些数字全部来自这台机器上的真实运行，不是估算。
你可以拿它判断"这东西在我电脑上能不能用"。

> 这组数据是 2026-11 上旬测的（提示词还没精简、也没有预热）。结论仍然成立，
> 之后的提速（预热重放、两级检索、精简 system）见下面「提速」一节，同一任务从 197 秒降到 56 秒。

### 9 个任务，全部正确

| 任务 | 耗时 | 走的路子 |
|---|---|---|
| data 目录里有几个文件 | **25 秒** | `run_cmd` 一条命令 |
| 统计各种文件类型各多少个 | 31 秒 | `skill count_ext` |
| 订单金额加起来多少 | **24 秒** | `skill sum_field` |
| test 里有没有重复文件 | 43 秒 | `skill find_duplicates` |
| 把 hello.txt 里的 hello 改成 HELLO | 68 秒 | read → replace → read → finish |
| orders.jsonl 有多少行 | 43 秒 | `run_cmd` |
| 新建 note.txt 写「你好世界」 | **44 秒** | `write_file` → finish |
| 看看有没有特别大的文件 | 93 秒 | `skill find_large` |
| 把 data 压缩成 zip | 31 秒 | `skill zip_dir` |

**最快 24 秒，最慢 93 秒，平均 45 秒。9 个任务全对。**

### 为什么有快有慢

**每步约 30 秒，步骤数决定总耗时。**

   1 步任务（数文件、求和、压缩）       → 25-31 秒
   2 步任务（新建文件、找大文件）       → 44-93 秒
   4 步任务（改文件：读→改→验证→收尾）  → 68 秒

30 秒里绝大部分是**处理提示词**，不是生成回答：

   每步要重新过一遍约 1000 token 的提示词
   41 tok/s × 24 秒 ≈ 1000 token

所以优化方向一直是「**少一步**」和「**提示词更短**」，不是「换个更快的模型」。

### 优化前后的对比

| | 优化前 | 优化后 |
|---|---|---|
| 提示词长度 | 2021 字符 | **1448 字符** |
| 数文件 | 80 秒 | **25 秒** |
| 新建文件 | 99 秒 | **44 秒** |
| 技能列表输出 | 3000+ 字符 | **1169 字符** |
| 工具选错导致空转 | 偶发 | 9 个任务 0 次 |

### 换模型折腾了一晚上，结论是没用

同一台机器上试过：

| 模型 | 结果 |
|---|---|
| Qwen3.8-4B-Distill | 中文退化，「一打鸡蛋加三个」答成 13 个 |
| xLAM-2-3B | 工具调用格式不稳，会编出不存在的路径 |
| Qwen3-1.7B | 简单任务准，真实环境会幻觉路径 |
| **Qwen3-4B-Instruct-2507** | **能干活，就它了** |

**但把提示词砍掉一半、给工具描述加上「什么时候别用」，任务快了 40%+。**

## 已知的限制

说实话：

**① 慢。** 4B 模型在四核 CPU 上约 3.7 token/秒（早期测的 6 tok/s 是短回答），首字还要等提示词算完。
简单任务几十秒，复杂的一两分钟。不是网卡了，是真的在算。

**② 复杂项目做不好。** 它能照着方法写脚本，但从零设计一个项目还不行——会跑偏、会写出有 bug 的逻辑。所以技能库很重要。

**③ 上下文有限。** 默认 6144（8 GB 纯 CPU 机器上 自动调参.bat 会压到 5120 甚至更低），扣掉提示词和工具定义，
输入预算约 5.4k，对话能用的约 2–3k token。长任务会记住前面的，但记不了太多。
想更大就得多内存：这台机器试过 6144 + KV 量化，prefill 从 39 掉到 13 token/秒，反而不能用了。

**④ 需要 Windows。** 纯 PowerShell，没打算跨平台。

**⑤ 有些工具要额外装东西。** 65 个工具里绝大多数开箱即用，但读 PDF 要 python+pypdf、
解 `.7z/.rar` 要 7-Zip、`install` 要 winget、联网类要能上网。
哪些能用、哪些不能用、缺了会报什么错、怎么自己验证，全在单独一份：
**[工具与能力边界](Document/06-工具与能力边界.md)**。

**⑥ GPU 模式要自己准备运行时。** 面板「设置 → 模型编译方式」有 CPU / GPU 两档，仓库只带 CPU 版 `llama\`。
选 GPU 前要把 CUDA 版 llama.cpp 解压到 `llama-gpu\`（里面要有 `llama-server.exe` 和配套 dll），
再点「初始化」——这一步只做检测，不会下载也不会编译；没放文件就点，会直接报
「没找到 llama-gpu\llama-server.exe」。

## 性能调优笔记（踩过的坑，别重复踩）

> 这节的耗时数字是**早期测的**（提示词还没精简、工具描述还没改）。结论仍然有效，
> 但现在的实际表现请对照上面「实测性能」那一节。

**① KV cache 量化在 CPU 上是负优化。**

`config.json` 里能开 `kvCacheTypeK` / `kvCacheTypeV`（把注意力缓存压到 8bit/4bit）。
确实省内存，但实测**速度掉一半**——反量化要额外算力，CPU 扛不住。

| 配置 | 单步耗时 | 内存 |
|---|---|---|
| 不量化，context 6144 | **68 秒** | 1.36 GB |
| 量化 q8_0/q4_0，context 8192 | 142 秒 | 1.24 GB |

**结论：纯 CPU 跑就别开量化。** 这招是给显卡用的。默认配置已经是不量化的最优解。

**② 上下文不是越大越好。**

f16 KV 下 5120 是这台 8GB 机器能稳住的上限（约 4.8 GB 占用，prefill 39 tok/s）。
再往上 6144 的 f16 装不下，只能换 q8_0 量化——而量化又必须开 flash attention，
prefill 直接掉到 13 tok/s，一个请求准备 5 分钟。**所以别为了数字大去开量化。**

**③ 工具定义按需发。**

Nafx 会按任务类型只发 4-8 个相关工具，不是全发 50 个。没匹配到任务类型时也只发 9 个常用的——这条改动让「找出所有 txt 文件」从 126 秒降到 50 秒。
这一步省了约 1000 token，直接体现在每步快十几秒上。

**④ 大文件别整个读。**

`read_file` 超过 550 字符就截断，给出"怎么继续看"的命令。
硬塞给模型只会撑爆上下文、拖慢速度。
