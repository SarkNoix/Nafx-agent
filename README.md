# Nafx

**一台普通电脑，一个能自己干活的 AI。**

不用显卡，不用联网，不花一分钱。四核 CPU + 8 GB 内存就能跑起来。

## 它和别的 agent 框架差在哪

我翻过 [188 个开源 agent harness](https://github.com/RyanAlberts/best-of-Agent-Harnesses)，
绝大多数要 Python、Node 或者 Docker。

Nafx 只用 **Windows 自带的 PowerShell**——不用装 Python，不用装 Node，不用装 Docker，
下载、解压、双击。

| | 大多数 agent 框架 | Nafx |
|---|---|---|
| 运行环境 | Python / Node / Docker | **系统自带 PowerShell** |
| 装依赖 | pip / npm | **不用装** |
| 内存 | 16 GB 起 | **8 GB 能跑** |
| 界面 | 英文 CLI | **中文面板** |
| 启动 | 敲命令 | **双击 bat** |

这个组合在我翻过的 188 个里没找到第二个。

**为什么走这条路**：不是"不想用 Python"，是**目标机器装不了**。
办公室淘汰的四核老机器、家里人用的笔记本——它们没有开发环境，
但一样需要一个能整理文件、算表格的助手。

![界面](images/panel.jpg)

跑完一个任务后的样子。左边是配置和当前状态，中间是过程：

- **每一步分两半** —— 上半是「做了什么」（工具名 + 参数 + 耗时），下半是「返回」（实际输出）
- **输入框上方有命令条** —— 一眼看到刚才跑了哪些命令
- **右下角那个 ∑** —— 点开能看 token 用量，还能装补丁改界面

图上是液态玻璃主题，右上角可以切成浅色或深色。

## 这是什么

Nafx 是一个跑在你自己电脑上的 AI 助手。你说话，它动手——读写文件、跑命令、处理表格、整理目录。

它有这些特点：

- **完全本地**：模型跑在你电脑上，数据不出门
- **不用显卡**：CPU 就能跑，核显机器也行
- **不花钱**：没有 API，没有订阅
- **能真干活**：24 个预设技能，常见活儿一句话搞定
- **可扩展**：加一个 `.ps1` 文件就是一个新技能
- **Windows 原生**：纯 PowerShell，不装 Python，不装 Node

## 它是怎么工作的

大部分人对 AI 助手的想象是"一个无所不能的大脑"。

**不是的。**

Nafx 的核心想法是：**模型只管判断，干活交给技能。**

```
你说："帮我找出这个文件夹里重复的文件"

模型做的：判断这活儿该用哪个技能   →  find_duplicates
技能做的：真正的活（算哈希、分组） →  直接出结果
```

模型不需要会写代码，只需要会**选**。选是它擅长的，写代码不是。

这就是为什么一个 4B 的小模型能干出像样的活。

### 为什么不直接让模型写代码

试过。它会：

- 写出来的逻辑有 bug（用哈希当键存文件名，同哈希的互相覆盖）
- 发现不了自己的 bug（输出"没找到重复"也照单全收）
- 或者干脆放弃计划，改成一个个手动读文件

这不是提示词能修的，是模型规模的问题。

**换个思路**：把"怎么干"提前写成验证过的脚本，模型只负责挑。

结果：

| | 让模型自己写 | 用技能库 |
|---|---|---|
| 找重复文件 | 700 秒，超时，结果错 | 204 秒，结果对 |

## 两套配置

仓库里有两个配置文件：

| 文件 | 怎么启动 | 用途 |
|---|---|---|
| `config.json` | 双击 `Nafx.bat` | 默认，开箱即用 |
| `config.self.json` | 双击 `Nafx 我的配置.bat` | **给自己用的**，参数更激进 |

**为什么不合并成一个**：默认配置要照顾别人机器（内存未知、权限保守）。你自己机器什么情况你最清楚，可以放开。

**`config.self.json` 里能改什么**：

```json
{
  "maxTokens": 700,        // 默认 500，给长了不容易截断工具参数
  "maxSteps": 40,          // 默认 30
  "stepTimeoutSeconds": 240,   // 默认 180，慢机器会误判超时
  "maxOutputChars": 1200,  // 默认 800，一次多看些输出
  "temperature": 0.25,     // 默认 0.3，更低更稳
  "allowAdmin": true,      // 默认 false，自己用直接开
  "personalPrompt": "..."  // ← 这个最有意思
}
```

**`personalPrompt` 是什么**：

一段话，会追加到系统提示词末尾。写你自己的习惯，模型每次都知道：

```json
"personalPrompt": "这台机器是我自己的，工作区在 E:\\Nafx\\workspace。\n我经常做的事：数文件、算订单金额、找重复文件、压缩打包。\n拿不准的时候先问，别猜。"
```

运行时日志里会显示 `带上个人指令（79 字符）`，能确认生效了。

**换配置启动的原理**：`launcher.ps1` 和 `monitor.ps1` 都支持 `-ConfigFile` 参数，`agent.ps1` 从环境变量 `NAFX_CONFIG` 读。想加第三套配置，复制一份改个名字就行。

## 换电脑了怎么办

Nafx 的参数是按机器算的，换台电脑直接跑可能不合适（内存小的会被换页拖死，内存大的又浪费）。

**双击 `自动调参.bat`**，它会：

```
1. 读你的 CPU 核数、内存大小、显卡、llama.cpp 是不是 CUDA 版
2. 算出这台机器最合适的参数
3. 和当前配置对比，告诉你差在哪
```

输出长这样：

```
CPU     Intel Core i3-10105F
        4 物理核 / 8 逻辑核
内存    7.85 GB（当前可用 1.13 GB）
显卡    NVIDIA GeForce GT 730（2 GB）
推理版  CPU 版（显卡用不上）

推荐值 vs 当前值
context                6144      6144   按内存和模型大小算
threads                   0 →       4   物理核数
maxTokens               500 →     600   核多给多点
maxSteps                 30 →      25   内存紧就少给
stepTimeoutSeconds      180 →     240   核少的机器超时给够
```

**双击 `自动调参并应用.bat`** 会先备份成 `config.json.bak`，再写进去。

**推荐值是怎么算的**：

```powershell
# 留给系统的：Windows + 浏览器 + agent，实测约 2.5 GB
# 安全余量：512 MB（吃满内存反而更慢）
# 每 token 的 KV cache：4B Q4 实测约 0.4 MB，按模型大小缩放

context = (总内存 - 2.5 - 模型大小 - 0.5) * 1024 / 每token内存
```

这套公式在 8 GB / 16 GB / 32 GB 上都对过，8 GB 跑 4B 算出来正好是 6144——和实测能吃住的值一致。

### 面板里也能改

右下角那个 `∑` → 往上滚到「配置」，六个参数直接改，保存就行。

**有范围校验**：context 不能超过 32768、threads 不能超过 32、超时不能低于 30 秒。填错了会被拒绝并告诉你正确范围。

改完要重启服务（面板会提示）。

## 技能库

`skills/` 里每个 `.ps1` 就是一个技能，`skill.json` 是索引。

现在有 24 个：

**文件** 找重复文件、按扩展名统计、找大文件、批量改名、比较文件、目录树、合并文件、重复行去重、清理空目录、按日期归档、批量解压、压缩成 zip

**文本** 文本统计、搜关键词、批量替换、日志提错误

**表格** CSV 统计、查某人某项、字段求和、CSV↔jsonl、Excel 转 CSV

**数据** 查 JSON / JSONL 字段，数字自动求和、平均、最大最小

**网页** 抓网页正文

### 加一个自己的技能

**1. 写个脚本** `skills/我的技能.ps1`

```powershell
param([string]$Path = '.')

# 干活
$files = Get-ChildItem $Path -File
Write-Output ("这里有 " + $files.Count + " 个文件")
```

**2. 在 `skills/skill.json` 里加一条**

```json
{
  "name": "my_skill",
  "title": "我的技能",
  "desc": "这个技能干什么",
  "triggers": ["触发词1", "触发词2"],
  "params": "-Path <目录>",
  "example": "skill(command=\"my_skill -Path test\")"
}
```

**3. 完事**

模型 `skill(command="list")` 就能看到它，中文名字也能匹配上。

**技能怎么写才好**：

- 开头写清楚这脚本干什么、怎么用
- 用 `param()` 声明参数，给默认值
- 出错时输出人能看懂的话，别直接抛异常
- **破坏性操作默认只预览**，加 `-Apply` 才真动手

## 自动训练器（train/）

Nafx 带一个自测自改的工具：**自己出题、按步骤判分、发现短板后改提示词、再重考**。

目标是把分数刷到 95 以上。

```powershell
# 完整训练：刷到 95 分，最多 3 轮
powershell -ExecutionPolicy Bypass -File train\train.ps1 -Target 95 -Rounds 3

# 快速冒烟：每轮抽 60% 的题
powershell -ExecutionPolicy Bypass -File train\train.ps1 -Quick -Rounds 2

# 只考某一类
powershell -ExecutionPolicy Bypass -File train\train.ps1 -Category 联网

# 只看题目和评分规则，不调模型
powershell -ExecutionPolicy Bypass -File train\train.ps1 -DryRun
```

**跑之前先把模型服务起来**（双击 `Nafx.bat`，或者确认 8080 端口活着）。

**题库**在 `train/bank.json`（约 96 KB），分好几类：文件操作、数据统计、联网、系统查询。

**每轮会做什么**：

```
1. 出题 → 让 agent 真做一遍
2. 按预设的评分规则判分（数字对不对、文件改没改、有没有编答案）
3. 统计哪类题错得多
4. 改提示词 / 改流程模板
5. 再考一遍，看分数涨没涨
```

**输出**在 `train/out/`：每轮的备份、报告、调参日志。

这是把「感觉变好了」换成「分数涨了多少」的办法。

## 实测性能（i3-10105F / 8 GB / 无显卡）

下面这些数字全部来自这台机器上的真实运行，不是估算。
你可以拿它判断"这东西在我电脑上能不能用"。

### 9 个任务，全部正确

| 任务 | 耗时 | 走的路子 |
|---|---|---|
| data 目录里有几个文件 | **25 秒** | `run_cmd` 一条命令 |
| 统计各种文件类型各多少个 | 31 秒 | `skill count_ext` |
| 订单金额加起来多少 | **24 秒** | `skill sum_field` |
| test 里有没有重复文件 | 43 秒 | `skill find_duplicates` |
| 把 hello.txt 里的 hello 改成 HELLO | 68 秒 | read → replace → read → finish |
| orders.jsonl 有多少行 | 43 秒 | `run_cmd` |
| 新建 note.txt 写「你好世界」 | **44 秒** | `write_file` → finish |
| 看看有没有特别大的文件 | 93 秒 | `skill find_large` |
| 把 data 压缩成 zip | 31 秒 | `skill zip_dir` |

**最快 24 秒，最慢 93 秒，平均 45 秒。9 个任务全对。**

### 为什么有快有慢

**每步约 30 秒，步骤数决定总耗时。**

   1 步任务（数文件、求和、压缩）       → 25-31 秒
   2 步任务（新建文件、找大文件）       → 44-93 秒
   4 步任务（改文件：读→改→验证→收尾）  → 68 秒

30 秒里绝大部分是**处理提示词**，不是生成回答：

   每步要重新过一遍约 1000 token 的提示词
   41 tok/s × 24 秒 ≈ 1000 token

所以优化方向一直是「**少一步**」和「**提示词更短**」，不是「换个更快的模型」。

### 优化前后的对比

| | 优化前 | 优化后 |
|---|---|---|
| 提示词长度 | 2021 字符 | **1448 字符** |
| 数文件 | 80 秒 | **25 秒** |
| 新建文件 | 99 秒 | **44 秒** |
| 技能列表输出 | 3000+ 字符 | **1169 字符** |
| 工具选错导致空转 | 偶发 | 9 个任务 0 次 |

### 换模型折腾了一晚上，结论是没用

同一台机器上试过：

| 模型 | 结果 |
|---|---|
| Qwen3.8-4B-Distill | 中文退化，「一打鸡蛋加三个」答成 13 个 |
| xLAM-2-3B | 工具调用格式不稳，会编出不存在的路径 |
| Qwen3-1.7B | 简单任务准，真实环境会幻觉路径 |
| **Qwen3-4B-Instruct-2507** | **能干活，就它了** |

**但把提示词砍掉一半、给工具描述加上「什么时候别用」，任务快了 40%+。**

## 已知的限制

说实话：

**① 慢。** 4B 模型在四核 CPU 上约 6 token/秒。简单任务几十秒，复杂的一两分钟。不是网卡了，是真的在算。

**② 复杂项目做不好。** 它能照着方法写脚本，但从零设计一个项目还不行——会跑偏、会写出有 bug 的逻辑。所以技能库很重要。

**③ 上下文有限。** 默认 6144，扣掉提示词和工具定义，对话能用的约 3300 token。长任务会记住前面的，但记不了太多。

**④ 需要 Windows。** 纯 PowerShell，没打算跨平台。

## 性能调优笔记（踩过的坑，别重复踩）

> 这节的耗时数字是**早期测的**（提示词还没精简、工具描述还没改）。结论仍然有效，
> 但现在的实际表现请对照上面「实测性能」那一节。

**① KV cache 量化在 CPU 上是负优化。**

`config.json` 里能开 `kvCacheTypeK` / `kvCacheTypeV`（把注意力缓存压到 8bit/4bit）。
确实省内存，但实测**速度掉一半**——反量化要额外算力，CPU 扛不住。

| 配置 | 单步耗时 | 内存 |
|---|---|---|
| 不量化，context 6144 | **68 秒** | 1.36 GB |
| 量化 q8_0/q4_0，context 8192 | 142 秒 | 1.24 GB |

**结论：纯 CPU 跑就别开量化。** 这招是给显卡用的。默认配置已经是不量化的最优解。

**② 上下文不是越大越好。**

同样 68 秒，context 5120 和 6144 一样快，再往上就开始慢了（prefill 变长）。6144 是这台机器的甜点。

**③ 工具定义按需发。**

Nafx 会按任务类型只发 4-8 个相关工具，不是全发 50 个。没匹配到任务类型时也只发 9 个常用的——这条改动让「找出所有 txt 文件」从 126 秒降到 50 秒。
这一步省了约 1000 token，直接体现在每步快十几秒上。

**④ 大文件别整个读。**

`read_file` 超过 550 字符就截断，给出"怎么继续看"的命令。
硬塞给模型只会撑爆上下文、拖慢速度。
