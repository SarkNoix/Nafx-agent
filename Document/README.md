## 一、哪些文档真正进入模型上下文

Nafx 不是把所有 Markdown 一次性塞给模型。当前请求的上下文按下面的顺序组装：

1. **系统提示词**：`agent/prompt.md`，启动时读入，所有请求共用。
2. **项目提示词**：`agent/project.md`，按任务类型挑相关段落，不是全量。写脚本/项目类任务会加载“最小项目模板、参数、验证”等段落。
3. **流程模板与工具定义**：`agent/flows.json` + `agent/tools-schema.json` 中当前流程需要的那几个工具，按任务裁剪。
4. **对话历史**：最近几轮原文；更早的历史在裁剪时生成摘要，摘要用于粗排，需要时再回读原文。
5. **经验记忆**：从 `agent/memory/lessons.jsonl` 里先按摘要/关键词粗排，再回读原文精排；命中的经验作为**任务消息之后的独立消息**注入，不塞进 system，避免破坏 prompt cache。
6. **当前任务文本**：最后一条 user 消息。

这样做的核心目的：**稳定前缀尽量不变（缓存命中），只有真正相关的内容才进上下文**。

## 二、文档清单与用途

### 01-系统提示词.md

来源：`agent/prompt.md`

真正进入 system 的主提示词。内容包括：

- Windows 环境约束：`run_cmd` 走 cmd，`run_ps` 走 PowerShell，不用 Linux 习惯命令。
- 工具调用格式：回复必须是工具 JSON，必须有真实 `name`，`finish` 也是工具。
- 先计划后动手：复杂任务先 `plan`，简单任务直接做；不许做完再补计划。
- 写脚本的参数规则：有 `param()` 就必须给 `command`；结果要能验证。
- 输出顺序：先 think 定这步，再动手，再用 note 汇报，不许倒序。

### 02-项目提示词.md

来源：`agent/project.md`

项目类/写脚本类任务的补充提示。当前新增了：

- PowerShell 字符串换行必须用反引号 `` `n ``，多行用 here-string，不能把 Markdown 三重反引号写进脚本。
- 一个脚本只能有一个 `param()` 块。
- 写文件用 `Set-Content -Path` / `Add-Content -Path`，`Out-File` 的参数是 `-FilePath`。
- “需求模糊”不等于“什么都不做”：先写三行目标卡，能合理默认就给最小可用版本，不把问题原样推回用户。
- 日志/记录类最小项目模板：一个入口脚本 + 一个数据文件 + 三行 README。

这份文档是**分段加载**的，不会整篇进 system。

### 03-工具手册.md

来源：`agent/工具手册.md`

工具级详细说明：每个工具的参数、边界、常见错误和推荐用法。它主要作为 `help` / 查阅资料使用，不整篇塞进上下文。模型先看精简的 tools schema，不确定时再查手册。

### 04-PowerShell手册.md

来源：`agent/shell手册.md`

PowerShell 语法、管道、文件操作、进程/服务、网络请求等参考。用于减少“把 Linux 命令搬过来”的错误，同样按需查阅。

### 05-错误处理.md

来源：`agent/错误处理.md`

常见报错的含义与修法：路径不存在、权限、编码、JSON 解析、网络代理、命令找不到等。目标是让模型先怀疑具体原因，而不是原样重跑。

### 06-工具与能力边界.md

来源：`工具与能力边界.md`

面向人的能力说明：哪些工具能做什么、哪些不能做、GPU 运行时要自己准备、模型文件为什么不进仓库、哪些操作会触发安全边界。**不进入模型上下文**，是交付/使用说明。

### 07-上下文两级检索与提速.md

来源：`docs/上下文两级检索与提速_20261123.md`

本轮上下文优化的设计说明：

- 会话/经验先摘要粗排，再回读原文精排。
- 裁历史时给早期对话生成摘要。
- 经验从 system 移到任务后的独立消息，保住 prompt cache。
- `--cache-prompt --cache-reuse 256` 的作用与实测数据。

### 08-交接报告.md

来源：`docs/交接报告.md`

项目结构、UI 组织、数据文件、常见坑和交接注意事项。面向维护者，不是模型提示。

### 09-优化说明.md

来源：`docs/优化说明_20261119.md`

大体量优化记录：启动、模型、上下文、工具、UI、训练等模块的改动原因和结果。适合查“为什么现在是这个设计”。

### 10-项目README.md

来源：`README.md`

对外主说明：安装、下模型、启动、配置、目录结构、常见问题、仓库地址。面向第一次使用的人。

### 11-使用说明.txt

来源：`使用说明.txt`

最短路径的快速使用说明，适合放在项目根目录直接看。

### 12-训练题库README.md

来源：`train/README.md`

训练器/题库的说明：题目格式、判分方式、单题回归、全量回归、报告位置。改题库或改判分前先看这份。

### 13-工具定义-tools-schema.json

来源：`agent/tools-schema.json`

机器可读的工具定义，是实际发给模型的 `tools` 段来源。它和 `03-工具手册.md` 的区别：

- schema 是**给模型看的精简参数定义**，决定模型能不能调、参数长什么样。
- 工具手册是**给人/模型查阅的详细说明**，解释边界、坑和推荐用法。

两者必须同步改：改了 schema 的参数，手册里的示例也要跟着改。

### 14-流程模板-flows.json

来源：`agent/flows.json`

按任务类型选择工具集合和流程模板。比如创建文件流程只带写文件/校验/收尾相关工具，不会把全部工具都塞进去。它决定了每次请求的 `flow`、可用工具数量和系统提示里的流程说明。

## 三、当前实时指标的数据链路

面板顶栏和气泡下的计量不是估算，链路如下：

1. `agent/agent.ps1` 每次模型请求后读取 llama-server 的 `timings`：
   - `predicted_per_second` → 生成速度 tok/s
   - `cache_n` / `prompt_n` → 缓存命中率、命中 token、新算 token
   - `predicted_n` → 本次生成 token
2. 写入 `agent/state.json`（面板 `/api/state` 快通道，运行中约 350ms 一次）。
3. 最终回答落盘时，把本轮汇总的 `tok/sec/speed/cacheHit/ctxUsed/ctxLimit` 写进 `agent/logs/session.jsonl`。
4. 面板 `renderLiveMeter()` 更新顶栏；`msgMeter()` 在最终回答气泡下渲染持久计量。
5. 点顶栏胶囊展开明细：缓存命中、命中 token、新算 token、生成速度、生成 token、上下文已用/实际、输入预算、提示词/历史/工具拆分。

关键点：**顶栏走 state 快通道，不再等 3.6 秒的慢通道；任务结束会立即补拉一次 session，避免最后一条回答延迟十几秒才上屏。**

## 四、维护约定

- 修改提示词：优先改 `agent/prompt.md` 或 `agent/project.md`，然后重跑单题回归，不要只改这里的副本。
- 修改工具说明：改 `agent/工具手册.md` / `agent/shell手册.md`，保持和 `tools-schema.json` 的实际参数一致。
- 修改上下文策略：同步更新 `docs/上下文两级检索与提速_20261123.md`，否则下次交接会对不上。
- 本文件夹的副本用于交付和阅读；源文件才是运行时真正读取的内容。
