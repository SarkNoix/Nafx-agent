# Nafx 工具手册

> 一句话原则：**每写下一个字，都要能在工具返回里找到出处。**

---

## 0. 找特定文件：别列全部目录

**这条是硬规则。**

要在目录里找某个名字的文件，**用 `run_cmd` 带通配符**，不要 `list_dir` 把整个目录列出来：

```
run_cmd(command="dir /b *test*")
run_cmd(command="dir /b /s *.log")
run_cmd(command="dir /b data\*.jsonl")
```

因为：

- `list_dir` 会把几百个文件名全塞进来，白占上下文
- `dir /b *关键词*` 只返回匹配的，一眼就看到
- 目录很大时，`list_dir` 直接爆上下文

**只有真的要看"这个目录里都有什么"时才用 list_dir。**

## 0. 30 秒速查

先看任务属于哪一类，再照右列办：

| 你听到的 | 你要做的 | 典型动作 |
|---|---|---|
| “有多少行 / 多少条” | 用命令数 | `run_cmd` → `write_file` |
| “总金额 / 合计 / 求和” | 能用 cmd 就 cmd，复杂用 PS | `run_cmd` 或 `run_ps` |
| “某个文件在哪” | 列目录 | `list_dir` |
| “看看有什么” | 列目录 | `list_dir` |
| “新建 / 写一个文件” | 直接写 | `write_file` |
| “改一下里面的 X” | 先读再替换 | `read_file` → `replace_in_file` |
| “把第 4 行改成 X” | 改某一行 | `set_line`（command 填 4） |
| “跑一下这个脚本” | 先建后跑 | `write_file` → `run_ps1` |
| “删掉临时文件” | 明确要求才删 | `delete_path` |
| “建个目录” | 建目录 | `make_dir` |
| “上网查一下 / 是什么 / 最新” | 先搜再读 | `web_search` → `web_fetch` |
| 闲聊、问概念 | 需要外部事实就搜 | 走聊天，或 `web_search` |
| “要算数 / 处理对象 / 解析 JSON / 正则” | cmd 做不了，用 PowerShell | `run_ps` |
| “解压这个包” | 直接解 | `unzip` |
| “压缩/打包” | 用技能 | `skill(zip_dir -Path 目录)` |
| “JSON 里某个字段” | 用技能 | `skill(json_query -Path x.json -Pattern 字段)` |
| “什么东西占内存 / 某某开着没” | 看进程 | `ps` |
| “装个某某软件” | 先搜后装 | `install`（先 `search `） |

**拿不准用什么工具，就调用 `help` 查。**

## 1. 通用规则

1. **一次一个动作**，做完停下等【观察】。
2. **看结果再决定下一步**，不要按原计划硬走。
3. **数字必须有出处**：写进文件的数字，必须在【观察】里出现过。
4. **失败就换路**：同一个动作不要重复第三次。
5. **不确定就查**：`help(command="工具名")`。
6. **做不到要说**：宁可承认，不要假装完成。
7. **原样使用**用户给的文件名，不翻译、不改写。
8. **任务里每个动作都要做**，包括最后的删除/清理。

## 2. 工具详解

### 2.1 write_file —— 写文件（新建或整体覆盖）

- **参数**：`path` 相对路径，`content` 完整内容
- **何时用**：产生新文件、整份重写
- **注意**：内容里的数字必须来自【观察】；不要把命令报错写进去（会被拒绝）

```json
{"think":"把查到的结果写进去","tool":"write_file","path":"count.txt","content":"订单数：27","find":"","replace":"","command":"","answer":""}
```

### 2.2 append_file —— 末尾追加一行

- **参数**：`path` 已存在的文件，`content` 一行内容
- **何时用**：往日志、清单里逐行追加
- **注意**：文件不存在会报错，先用 `write_file` 建

```json
{"think":"再补一行记录","tool":"append_file","path":"log.txt","content":"第 2 条：完成","find":"","replace":"","command":"","answer":""}
```

### 2.3 set_line —— 改第 N 行

- **参数**：`path` 目标文件，`command` 行号（写成 `4`），`content` 这一行要变成什么
- **何时用**：改某一行、在某一行插入内容
- **注意**：行号超过现有行数会报错；刚好等于行数+1 时等于追加一行

```json
{"think":"要把第四行改成 444","tool":"set_line","path":"work.txt","command":"4","content":"444","find":"","replace":"","answer":""}
```
### 2.3b find_files —— 按通配符找文件

- **参数**：`path` 从哪个目录找；`command` 通配符（如 `*.txt`）
- **会递归**，输出带文件大小
- **比 `run_cmd(dir /b *词*)` 好在**：不用记 cmd 语法、自动递归、带大小

```json
{"think":"找所有 txt","tool":"find_files","path":".","command":"*.txt","content":"","find":"","replace":"","answer":""}
```

**什么时候用**：任务说"找一下所有 .log 文件"、"有哪些 csv"。

**什么时候不用**：只是数个数 → `run_cmd(dir /b | find /c /v "")` 更快。

### 2.3c file_info —— 看文件详情

- **参数**：`path` 文件或目录
- 文件返回：大小、修改时间、是否只读
- 目录返回：文件数、总大小

```json
{"think":"看这个文件多大","tool":"file_info","path":"data/orders.jsonl","content":"","find":"","replace":"","command":"","answer":""}
```

**替代** `run_cmd(dir 文件)`，输出更清楚。

### 2.3d move_path / copy_path —— 移动、复制

- **参数**：`path` 源；`command` 目标路径
- 目标目录不存在会自动建
- **目标已存在会报错**，不会静默覆盖

```json
{"think":"改名","tool":"move_path","path":"a.txt","command":"b.txt","content":"","find":"","replace":"","answer":""}
```

**同名就是重命名**：把 `a.txt` 移到 `b.txt`，等于改名。

### 2.3e grep_file —— 文件内搜关键词

- **参数**：`path` 文件；`command` 关键词；`content` 上下文行数（1-5，可空）
- 返回行号，命中的行前面标 `>`

```json
{"think":"找报错在哪行","tool":"grep_file","path":"app.log","command":"ERROR","content":"2","find":"","replace":"","answer":""}
```

**比 read_file 好在**：大文件不用整个读，只返回命中的那几行。

**比 findstr 好在**：输出是给人看的格式，不用自己解析。

### 2.3f hash_file —— 算文件哈希

- **参数**：`path` 文件；`command` 算法（md5 / sha1 / sha256，默认 sha256）
- 用途：判断两个文件是不是**完全一样**

```json
{"think":"比这两个","tool":"hash_file","path":"a.txt","command":"md5","content":"","find":"","replace":"","answer":""}
```

**什么时候用**：要确认"这两个文件真的相同吗"，比 `compare_files` 更细（能直接看哈希）。

**别用**：只想知道大小 → `file_info`。

### 2.3g read_lines —— 按行号读

- **参数**：`path` 文件；`command` 从第几行开始；`content` 读多少行（默认 40，最多 200）

```json
{"think":"看 100-120 行","tool":"read_lines","path":"app.log","command":"100","content":"20","find":"","replace":"","answer":""}
```

**什么时候用**：文件很大，只想看某一段。**比 `read_file` 好**——不会截断后不知道看到哪了。

**读完会告诉你**「还有 N 行，接着读用 command=某行号」。

### 2.3h sys_info —— 看机器配置

- **参数**：`command` 填 `cpu` / `mem` / `disk` / `all`（留空 = all）

```json
{"think":"看内存","tool":"sys_info","command":"mem","path":"","content":"","find":"","replace":"","answer":""}
```

输出：

```
CPU  Intel(R) Core(TM) i3-10105F CPU @ 3.70GHz
     4 物理核 / 8 逻辑核
内存  共 7.85 GB，可用 0.66 GB
磁盘  C: 共 80 GB，可用 45.6 GB
```

**别用**：`run_cmd wmic` 那一堆，输出又长又要自己解析。

### 2.3i clipboard —— 剪贴板

- **参数**：`command` 填 `get` 或 `set`；`set` 时正文放 `content`

```json
{"think":"看剪贴板","tool":"clipboard","command":"get","path":"","content":"","find":"","replace":"","answer":""}
```

**什么时候用**：要把一段文字交给用户（`set`），或者用户说"从剪贴板里的内容…"（`get`）。

### 2.3j now —— 当前时间

- **无参数**

```json
{"think":"今天几号","tool":"now","path":"","content":"","find":"","replace":"","command":"","answer":""}
```

输出：`现在是 2026年11月10日 星期二 17:18:35`

**必须用**：任何跟日期、星期、时间有关的任务。**你的训练数据有截止日期，不要自己猜今天是几号。**

### 2.3k zip_list —— 看压缩包里有什么

- **参数**：`path` 压缩包（zip / docx / xlsx / pptx）

```json
{"think":"里面有什么","tool":"zip_list","path":"backup.zip","content":"","find":"","replace":"","command":"","answer":""}
```

**什么时候用**：不确定包里是什么，先看一眼再决定解不解。

### 2.3l diff_files —— 比两个文件

- **参数**：`path` 第一个文件；`command` 第二个文件

```json
{"think":"改了什么","tool":"diff_files","path":"a.txt","command":"a.txt.bak","content":"","find":"","replace":"","answer":""}
```

输出逐行对比，告诉你第几行、前后各是什么。

**什么时候用**：改了文件想确认改对没有，比重新读一遍直观。

### 2.3m json_format —— 美化或压缩 JSON

- **参数**：`path` JSON 文件；`command` 填 `pretty`（缩进）或 `compact`（一行）
- 加 `content: "1"` 表示写回文件，否则只显示

```json
{"think":"看看结构","tool":"json_format","path":"config.json","command":"pretty","content":"","find":"","replace":"","answer":""}
```

### 2.3n csv_preview —— 先看 CSV 长什么样

- **参数**：`path` CSV 文件；`command` 看几行（默认 8）

```json
{"think":"有什么列","tool":"csv_preview","path":"staff.csv","command":"5","content":"","find":"","replace":"","answer":""}
```

输出列名 + 前几行。**先预览再决定用 csv_stats 还是 csv_query。**

### 2.3o date_calc —— 算日期

- **参数**：`command` 填天数（`3` = 三天后，`-7` = 七天前）或日期（`2024-01-01`，算距今多少天）

```json
{"think":"三周后是几号","tool":"date_calc","command":"21","path":"","content":"","find":"","replace":"","answer":""}
```

**什么时候用**：「几天后是几号」「离某天还有多少天」。

**别用**：`run_cmd` 去算——那要跑好几次命令，还容易算错。

### 2.3p download_file —— 下载文件

- **参数**：`path` 填 http/https 网址；`command` 填存到哪（留空用原文件名）

```json
{"think":"下这个文件","tool":"download_file","path":"https://example.com/a.zip","command":"a.zip","content":"","find":"","replace":"","answer":""}
```

**和 `web_fetch` 的区别**：`web_fetch` 只是把内容显示出来（看网页文字用），`download_file` 是**真的存到磁盘上**。

### 2.3q env_get —— 看环境变量

- **参数**：`command` 填变量名（留空列出 USERPROFILE/TEMP/PATH 等常见几个）

```json
{"think":"家目录在哪","tool":"env_get","command":"USERPROFILE","path":"","content":"","find":"","replace":"","answer":""}
```

### 2.4 replace_in_file —— 替换第一处

- **参数**：`path`、`find` 原文（要精确）、`replace` 新文
- **何时用**：只改一小段，不想重写全文
- **注意**：只替换第一次出现；找不到会报错 → 先 `read_file` 看原文

```json
{"think":"把旧的价格改成新的","tool":"replace_in_file","path":"config.txt","find":"price=10","replace":"price=20","command":"","answer":""}
```

### 2.4b multi_edit —— 一次改多处

- **参数**：`path`、`edits`（数组，每项 `{find, replace}`，按顺序执行）
- **何时用**：同一文件要改 3 处以上。一次提交，比来回 `replace_in_file` 少好几个回合（每回合几十秒）
- **注意**：`find` 必须和文件里一字不差（含缩进）；哪一处没匹配上会在结果里点名、那一处不改

```json
{"think":"改三处：函数名、参数、调用","tool":"multi_edit","path":"calc.ps1","content":"","command":"","answer":"",
 "edits":[{"find":"function Add","replace":"function Add-Num"},{"find":"$a + $b","replace":"$a + $b + $c"},{"find":"Add 1 2","replace":"Add-Num 1 2 3"}]}
```

### 2.4c read_file —— 读内容

- **参数**：`path`
- **何时用**：确认内容、取原文、改之前先看
- **注意**：大文件截断到 3000 字符；**数行数不要用它，用 `run_cmd`**

```json
{"think":"先看看文件里到底写了什么","tool":"read_file","path":"data\\orders.jsonl","content":"","find":"","replace":"","command":"","answer":""}
```

### 2.5 list_dir —— 列目录

- **参数**：`path` 目录，根目录填 `"."`
- **何时用**：不知道有什么、确认文件在不在
- **返回**：`[文件] 名字  大小`
- **大目录**：超过 80 条只列前 60 条，末尾会提示「目录里东西太多」。这时别反复 list_dir，直接 `find_files`（递归按名字找）或 `grep_file`（path 给目录按内容找）。

```json
{"think":"先看看 data 里有什么","tool":"list_dir","path":"data","content":"","find":"","replace":"","command":"","answer":""}
```

### 2.6 delete_path —— 删除

- **参数**：`path`
- **何时用**：任务**明确**要求清理
- **注意**：没要求就别删；不能删 workspace 根目录

```json
{"think":"任务要求跑完就删，把它删掉","tool":"delete_path","path":"temp.bat","content":"","find":"","replace":"","command":"","answer":""}
```

### 2.7 run_ps1 —— 运行 PowerShell 脚本

- **参数**：`path` 已存在的 .ps1，`command` 可选传参
- **何时用**：需要循环、计算、生成报表
- **注意**：脚本必须先 `write_file` 建出来；返回里有真实退出码

```json
{"think":"脚本建好了，跑一下看结果","tool":"run_ps1","path":"calc.ps1","content":"","find":"","replace":"","command":"","answer":""}
```

### 2.8 run_bat —— 运行批处理

- **参数**：`path` 已存在的 .bat
- **何时用**：跑现成的批处理
- **注意**：`.ps1` 不能用它跑，会失败

### 2.9 run_cmd —— 执行命令（cmd）

- **参数**：`command` 纯 cmd 语法；`path` **必须留空**
- **何时用**：数数、查找、列文件、看大小 —— **能算的都让它算，你自己算不准**

命令速查（照抄，不要自己发明）：

| 想干什么 | 命令 |
|---|---|
| 列文件 | `dir /b data` |
| 数行数 | `find /c /v "" data\orders.jsonl` |
| 找关键词 | `findstr /c:"键盘" data\orders.jsonl` |
| 带行号看内容 | `findstr /n "." data\orders.jsonl` |
| 看文件大小 | `dir data\orders.jsonl` |
| 看全文 | `type data\orders.jsonl` |

```json
{"think":"需要知道有多少行，用命令数最快","tool":"run_cmd","path":"","content":"","find":"","replace":"","command":"find /c /v \"\" data\\orders.jsonl","answer":""}
```

**注意**
- 不要写 `cmd /c` 前缀
- 路径用反斜杠
- `format`、`diskpart`、`shutdown` 会被直接拒绝

### 2.10 help —— 查这本手册

- **参数**：`command` 填工具名或关键词，如 `run_cmd`、`错误`、`write_file`
- **何时用**：不确定参数、连续失败、不知道该用哪个工具

```json
{"think":"不确定该用哪个工具，先查手册","tool":"help","path":"","content":"","find":"","replace":"","command":"run_cmd","answer":""}
```

### 2.11 make_dir —— 创建目录

- **参数**：`path` 目录路径，可以多层，如 `reports/weekly`
- **何时用**：要建一个空目录，或者先建好目录再往里写文件
- **注意**：已经存在会直接告诉你，不会报错；`write_file` 也会自动建父目录，所以不算必须

```json
{"think":"先把报告目录建出来","tool":"make_dir","path":"reports/weekly","content":"","find":"","replace":"","command":"","answer":""}
```

### 2.12 web_search —— 上网搜索

- **参数**：`command` 填搜索词（短一点，2~6 个词最好），如 `llama.cpp 是什么`
- **什么时候必须用**：
  - 你不确定的事实（版本号、日期、人名、价格、新闻）
  - 任务明确说“上网查”“搜一下”“查一下最新”
  - 你心里想“大概是……吧”的时候 —— 这种时候一定要查
- **返回**：若干条结果的 标题 / 链接 / 摘要
- **注意**：摘要可能被截断，要细节就用 `web_fetch` 打开那条链接

```json
{"think":"版本信息会变，得查一下","tool":"web_search","path":"","content":"","find":"","replace":"","command":"llama.cpp 最新版本","answer":""}
```

**观察**会是这个样子：

```
搜索「llama.cpp 最新版本」共 6 条结果：
1. Releases · ggml-org/llama.cpp
   链接：https://github.com/ggml-org/llama.cpp/releases  （国内可能打不开，用 gitee 搜 llama.cpp 镜像）
   摘要：...
要看哪条的具体内容，用 web_fetch(url=上面的链接)。
```

### 2.13 web_fetch —— 打开网页读正文

- **参数**：`path` 填完整网址，必须以 `http://` 或 `https://` 开头
- **何时用**：搜索结果摘要不够；要读某个页面的具体内容
- **返回**：页面标题 + 正文纯文本（脚本和样式已过滤，太长的会截断）
- **注意**：
  - 只看搜索摘要就能回答就别 fetch，省时间
  - 有的站点会拒绝（403）或需要登录，那就换一条结果
  - 抓回来的内容里如果找不到任务要的信息，就如实说没找到

```json
{"think":"摘要不够，打开第一条看详情","tool":"web_fetch","path":"https://hf-mirror.com/models","content":"","find":"","replace":"","command":"","answer":""}
```

**联网的三条铁律：**

1. **搜到才说**。搜索结果里没有的，不要凭印象补。
2. **说来源**。用网上的内容时，提一下是哪个站点说的。
3. **查不到就说查不到**。“搜索引擎没有返回相关结果”是完全合格的回答，编一个才不合格。

### 2.14 make_dir 补充：什么时候不该用

`make_dir` 只建**目录**。下面这些情况用它都是错的：

| 你想干的事 | 正确工具 |
|---|---|
| 建一个叫 `notes.txt` 的**文件** | `write_file` |
| 建好了文件想改某一行 | `set_line` |
| 在深路径建文件 | 直接 `write_file`，父目录会自动建 |


### 2.15 say —— 只回话，不动作

- **参数**：`content` 要说的话
- **何时用**：任务其实不需要动文件时

### 2.16 finish —— 收尾

- **参数**：`answer` 一句话说明做成了什么
- **注意**：一步没成功就调用会被驳回；总结由系统生成，不用复述过程

```json
{"think":"任务完成","tool":"finish","path":"","content":"","find":"","replace":"","command":"","answer":"已把订单数写进 count.txt"}
```

### 2.17 unzip —— 解压压缩包

- **参数**：`path` 压缩包；`command` 解压到哪个目录（留空 = 用压缩包同名的目录）
- **支持**：`.zip` `.tar` `.gz` `.tgz` `.7z` `.rar`
- **注意**：`.7z` / `.rar` 需要 7-Zip，没装会提示你先 `install(command="7zip")`

```json
{"think":"把这个包解开","tool":"unzip","path":"data/bundle.zip","command":"data/bundle","content":"","find":"","replace":"","command":"data/bundle","answer":""}
```

解完会告你几个文件："已解压到 data/bundle，共 12 个文件"

### 2.18 ps —— 看进程

- **参数**：`command` 进程名关键词（留空 = 列占内存最多的 20 个）
- **用途**：查什么东西在吃内存、某个程序开没开
- **注意**：这是只看不下手。真要结束进程用 `run_cmd(command="taskkill /F /PID 1234")`

```json
{"think":"看看内存被谁占了","tool":"ps","path":"","content":"","find":"","replace":"","command":"","answer":""}
```

输出长这样：
```
占内存最多的 20 个进程，共 5561 MB：
llama-server             2,961 MB  PID 12788
QQ                         353 MB  PID 10736
```

按名字查：`ps(command="chrome")` → 只列 chrome 相关的

### 2.19 install —— 装软件

- **参数**：`command` 软件名。加 `search ` 前缀只搜不装
- **前提**：这台机器要有 winget（Win10 1909+ 一般都有）
- **注意**：装的时候是静默的，不会弹窗让你点；装完告诉你结果

```json
{"think":"先看看有没有这个软件","tool":"install","path":"","content":"","find":"","replace":"","command":"search 7zip","answer":""}
```

搜到之后再用包 ID 装：
```json
{"think":"装 7-Zip","tool":"install","path":"","content":"","find":"","replace":"","command":"7zip.7zip","answer":""}
```

**装之前最好先 search**，确认包名和 ID 对得上。装错了很难退。

### 2.19b run_ps —— 直接跑 PowerShell 命令

- **参数**：`command` 一条 PowerShell 命令（不用先写文件）
- **什么时候用**：`run_cmd` 做不了的——算数、对象、管道、cmdlet、JSON、正则
- **什么时候别用**：简单命令用 `run_cmd` 更快；写好的脚本反复跑用 `run_ps1`

```json
{"think":"算一下总大小","tool":"run_ps","command":"(Get-ChildItem *.txt | Measure-Object Length -Sum).Sum","content":"","find":"","replace":"","answer":""}
```

**cmd 做不了、PowerShell 能做的**：

| 想干的事 | run_ps 怎么写 |
|---|---|
| 求和 / 平均 / 最大 | `(1..100 \| Measure-Object -Sum).Sum` |
| 按属性排序取前几个 | `Get-Process \| Sort-Object WorkingSet64 -Desc \| Select-Object -First 3` |
| 解析 JSON | `'{"a":1}' \| ConvertFrom-Json` |
| 正则匹配 | `'abc123' -match '\d+'` |
| 算日期差 | `((Get-Date) - (Get-Date '2026-01-01')).Days` |
| 分组统计 | `Get-ChildItem \| Group-Object Extension` |
| 格式化输出 | `... \| Format-Table -AutoSize` |

**会被拒绝的命令**：

- `Stop-Computer` / `Restart-Computer` —— 不能关机重启
- `Format-Volume` / `Clear-Disk` —— 不能格式化磁盘
- `Read-Host` / `Out-GridView` —— 会停下来等人，永远返回不了

**输出中文能正常显示**（内部强制 UTF-8）。

**多条命令用分号连**：

```powershell
run_ps(command="$n = (Get-ChildItem).Count; Write-Output ('共 ' + $n + ' 个')")
```

### 2.20 run_js —— 运行 JavaScript

- **参数**：`path` 脚本路径；`command` 额外参数（一般不用）
- **用的是 Windows 自带的 JScript**，不用装 Node
- **中文能正常输出**（内部会自动转编码）

```json
{"think":"用 JS 算一下","tool":"run_js","path":"calc.js","content":"","find":"","replace":"","command":"","answer":""}
```

脚本里这样输出：

```javascript
var sum = 0;
for (var i = 1; i <= 100; i++) sum += i;
WScript.Echo('1 加到 100 等于 ' + sum);
```

**注意**：

- 只能用 `WScript.Echo(...)` 输出，不能用 `console.log`
- 这是老版 JScript（ES3），**没有** `let` / 箭头函数 / `Array.map` 之类
- 写数组用 `var a = [1,2,3];`，循环用 `for (var i=0;...)`
- 拿命令行参数用 `WScript.Arguments`

**什么时候用 JS 而不是 PowerShell**：

能用 PowerShell 就用 PowerShell（前面那些工具都是）。JS 只在用户明确要求写 JS 脚本时用。

## 3. 标准流程

### A. 统计 → 写报告
```
run_cmd    find /c /v "" data\orders.jsonl    → 27
write_file report.txt  订单数：27              ← 数字来自上一步
finish
```

### B. 新建 → 确认
```
write_file notes.txt  "内容"
read_file  notes.txt
finish
```

### C. 写脚本 → 运行 → 存结果
```
write_file calc.ps1  "<脚本>"
run_ps1    calc.ps1                            → 看退出码和输出
write_file result.txt "<输出里的结果>"
finish
```

### D. 找文件
```
list_dir data
finish
```

### E. 改一小段
```
read_file        config.txt
replace_in_file  find="旧值" replace="新值"
finish
```

## 4. 系统会替你做的事

这些不是你该操心的，知道就好，别重复劳动：

| 系统行为 | 说明 |
|---|---|
| **预查** | 统计类任务，系统会先用命令算出真实数字，直接放进任务里 |
| **数字校验** | 你写进文件的数字若没在工具结果里出现过，会被驳回 |
| **漏步核对** | 说了删除却没用 `delete_path`、该写文件却没写，会被打回重做 |
| **重复保护** | 同一个动作重复太多次会被强制收尾 |
| **失败收尾** | 连续三次失败，系统会停止并如实说明原因 |

## 5. 出错怎么办（错误处理）

```
1. 看【观察】末尾的【提示】——系统已把报错翻译成下一步建议
2. 按提示改一次
3. 还不行 → 换一个完全不同的工具（别用同样参数重试）
4. 不确定 → help(command="工具名")
5. 连续失败三次会强制收尾
6. 真做不到 → finish，answer 写“做不到，原因是…”
```

### 报错对照

| 报错 | 意思 | 怎么办 |
|---|---|---|
| `'xxx' 不是内部或外部命令` | 命令名错 / 不是 cmd 命令 | 照速查表重写，或改用 read_file |
| `系统找不到指定的路径` | 路径写错 | 先 list_dir |
| `文件不存在` | 文件没有 | list_dir 确认，或先 write_file |
| `脚本不存在` | 还没建文件 | 先 write_file |
| `command 不能为空` | run_cmd 没填命令 | 命令写在 command，path 留空 |
| `被安全策略拒绝` | 越权操作 | 只能用 workspace 内路径 |
| `退出码 1` | 命令跑了但报错 | 看错误输出改参数 |
| `超时` | 命令卡住 | 换更快返回的命令 |

### 三条铁律

1. **不许把失败说成成功**——一步没成功就报完成，会被驳回并标成“没做成”。
2. **不许编数字**——写进文件的数字必须有出处。
3. **实在不行要说出来**——沉默结束比承认失败更糟。

## 6. 常见误区

| 误区 | 后果 | 正确做法 |
|---|---|---|
| 没建文件就 run_ps1 | 报“脚本不存在” | 先 write_file |
| 数字凭印象写 | 被驳回归零重来 | 用 run_cmd 查真实值 |
| 同一动作反复调 | 触发重复保护，被强制结束 | 换工具或直接 finish |
| `.ps1` 用 run_bat 跑 | 执行失败 | 看扩展名选工具 |
| 命令里带 `cmd /c` | 嵌套失败 | 只写命令本身 |
| 该删的不删就 finish | 被打回 | 补 delete_path |
| 该写文件却只口头说 | 被打回 | 补 write_file |
| 用 write_file 改某一行 | 整个文件被冲掉 | 用 set_line |
| **把 finish 打成文字** | 系统认不出来，一路空转到步数用完 | 在 tool_calls 里调，别在回答里打 `finish(answer="...")` |
| **run_ps1 跑数据文件** | 报“不是脚本”，白跑一步 | 先用 write_file 写 .ps1，再跑那个脚本 |
| **深层路径少写一级** | 文件建到别处去了 | 任务给几级就写几级，建完核一遍 |
| **jsonl 用 ConvertFrom-Json 整个读** | 报“无效的 JSON 基元” | 逐行读，见 shell 手册 2.4 |
| **任务没提的文件也去改** | 打乱用户的东西 | 只动任务点名的文件 |
| **答案到手还去“确认”一遍** | 重复动作被强制收尾 | 结果看一眼够用就 finish |

## 7. 特殊问题处理（权限、占用、编码、路径）

遇到下面这些情况，先照着做，别再瞎试。

### 7.1 路径写法（优先用正斜杠）

路径一律写成 `data/orders.jsonl`。

反斜杠 `\` 在 JSON 里是转义符，`\n`、`\t` 会被吃掉变成换行和制表符，路径就废了。
正斜杠 Windows 同样认，不会有这个问题。

### 7.2 路径里有空格

路径含空格时，命令里必须加引号：

```
dir "data\my folder"
type "data\订单 汇总.txt"
```

### 7.3 文件是只读的

`write_file` 已经会自动去掉只读属性再写一次。
如果还失败，多半是被别的程序占着，见 7.3。

### 7.4 文件被占用（正被其他程序使用）

不要硬写同一个文件。两个办法：

```
1. 换个文件名写：report_2.txt
2. 换个目录写：data\report.txt
```

### 7.5 中文乱码

系统跑命令时已经切到 UTF-8（`chcp 65001`）。
如果读文件看到乱码，说明文件本身是 GBK 编码，用：

```
powershell -NoProfile -Command "Get-Content -Encoding Default 'data\a.txt'"
```

### 7.6 文件很大，不要整个读

`read_file` 超过 3000 字符会被截断。要知道有多少行，用：

```
find /c /v "" data\big.log
```

要看前几行：

```
findstr /n "." data\big.log
```

### 7.7 命令没有任何输出

多半是这两种：

| 情况 | 怎么确认 |
|---|---|
| 路径不对 / 文件不存在 | 先 `dir data` 看看 |
| 没有匹配到内容 | `findstr` 没结果就是没匹配，不是出错 |

**空输出不等于失败**，看退出码：0 就是成功。

### 7.8 输出太长刷屏

加过滤，只取你要的部分：

```
dir /b data                    ← 只列名字，不列详情
findstr /c:"键盘" data\orders.jsonl
type data\x.txt | find /c "2026"
```

### 7.9 命令里出现 `&` `|` `>` 这些符号

它们是 cmd 的语法符号，不是普通字符。想输出这些字符要用 `^` 转义：

```
echo 1 ^& 2          → 输出 1 & 2
```

写文件内容时不用管，`write_file` 是直接写字节，不做解析。

### 7.10 JSON 内容里带引号

工具参数是 JSON，内容里的双引号要写成 `\"`：

```json
{"tool":"write_file","path":"note.txt","content":"他说\"你好\"","...":"..."}
```

### 7.11 会卡住的命令（禁止）

这些命令会等人按键，机器上跑永远不返回，工具会直接拒绝：

```
pause
choice
set /p
```

### 7.12 目录里有隐藏文件

`dir` 默认不显示隐藏文件，加 `/a`：

```
dir /a data
```

### 7.13 深层目录不存在

`write_file` 会自动创建中间的目录，不用手动 `mkdir`。

### 7.14 什么时候该放弃

连续两次同一个思路失败，就别再试了。判断标准：

- 同一类错误出现两次以上
- 提示里说的办法都试过了
- 再试也只能用同样的参数

这时候调用 `finish`，answer 写清楚：

```
做不到，因为 data 目录里没有 orders.jsonl 这个文件。
```

## 8. 多文件查看/编辑：file_editor

一次看多个文件：

```
file_editor(action="view", paths=["a.py","b.js","README.md"])
```

`view` 会带行号、文件类型、编辑建议、运行建议；默认单文件 120 行、多文件每个 45 行，总输出有上限。看整个目录用 `list_dir`，不要用 `view` 硬列。

| 动作 | 用途 |
|---|---|
| `view` | 看一个/多个文件，带类型和运行提示 |
| `write` | 新建或整体重写一个文件；写前自动备份 |
| `replace` | 跨多个文件做精确字符串替换，只改命中的文件 |
| `append` | 追加到文件末尾 |
| `insert` | 在指定行前插入 |
| `run` | 按后缀选运行器执行 |
| `types` | 查后缀指南；`find=".py"` 只看 Python |

### 8.1 后缀与运行

| 后缀 | 是什么 | 运行 |
|---|---|---|
| `.ps1` | PowerShell | `file_editor run` / `run_ps1`，有 `param()` 必须传参 |
| `.bat` `.cmd` | CMD 批处理 | `file_editor run` / `run_bat` |
| `.py` | Python | `file_editor run`（`python -u`） |
| `.js` `.mjs` `.cjs` | JavaScript | `file_editor run`（Node） |
| `.sh` | Shell | `file_editor run`（Git Bash） |
| `.exe` | 可执行程序 | `file_editor run`，参数放 `command` |
| `.json` | JSON | 不可执行；`run` 只校验合法性 |
| `.html` | 页面 | 不直接执行，浏览器/本地服务打开 |
| `.zip` `.pdf` `.docx` `.xlsx` `.png` | 压缩包/文档/图片 | 二进制，不能文本改；走专用工具 |

写 `.ps1` 会做语法检查，写 `.json` 会做严格 JSON 校验；不合法直接拒绝，不会写坏文件。二进制文件拒绝当文本改。

## 9. Git：只做安全动作

```
git(action="status", path="E:\repo")
git(action="diff", path="E:\repo")
git(action="add", path="E:\repo", files="a.py;README.md")
git(action="commit", path="E:\repo", message="feat: 说明")
```

支持 `status` / `diff` / `log` / `show` / `branch` / `remote` / `add` / `commit` / `fetch` / `pull` / `push` / `init` / `clone`；clone 支持 http(s)/ssh/git@/file://。

**规则**：不 `reset --hard`、不 `clean -f`、不 `rebase`、不 `push --force`；`pull` 只 `--ff-only`；只暂存任务相关文件，不无脑 `add .`。不是 Git 仓库时先问/确认，不擅自 `init`。

## 10. 不会就查：web_search / web_fetch

- 不熟的库、API、报错、版本、官方文档 → `web_search(command="关键词")`。
- 摘要不够 → `web_fetch(path="具体 URL")`，只抓最相关的一两条。
- 搜完把来源链接写进回答；搜不到就如实说搜不到，不凭记忆编。
- 本机文件/进程/端口用本机工具；Windows 命令细节用 `syshelp` / `win_doc`。
