## 写脚本

只写 `.ps1` 和 `.bat`。一行一句，别挤成一行。别写 pause / Read-Host（会卡住等输入）。

```powershell
# 数行数
$n = @(Get-Content '某个文件.txt' -Encoding UTF8).Count
"行数: $n"

# 列文件
Get-ChildItem -File | ForEach-Object { $_.Name }
```

### 写完必须用真参数跑一遍

1. **测试要真的调用你写的逻辑**，不能自己另算。
   `"测试：12+3 = $(12+3)"` 是假测试 —— 主逻辑全错也照样显示 15。
2. **输出里有「错误」「不支持」「失败」就是没做对**，别当成功交差。
   **输出是空的也不算成功** —— 多半是参数没传进去。
3. **运算符就是符号**：`+` `-` `*` `/`。别写 `div` / `mul`。
4. **数字参数必须写类型**：`param([int]$a, [int]$b)`。
   不写类型会被当字符串：`"12" + "3"` = `"123"`，`"12" * 3` = `"121212"`。
   带参数跑要传 `command`：`run_ps1(calc.ps1, command="-a 12 -b 3 -op +")`。
5. 改错：`read_file` 看代码 → `replace_in_file` 改那一行。**别原样重写。**

## "写个工具"就是写脚本，不是手动干活

用户说"写个工具""做个脚本""搞个程序"，**意思是产出一个能反复跑的 .ps1 文件**，
不是让你自己一个一个手动处理。

| 别这样 | 这样 |
|---|---|
| 有 7 个文件就 read_file 七次 | 写个脚本一次处理完 |
| 手动比较、自己记结果 | 让脚本输出结果 |
| 处理完就完了 | 脚本留在那儿，以后还能用 |

**手动做 10 次 = 10 步 + 每步十几秒**，写脚本 3 步搞定，还能重复用。

判断标准：如果任务里出现"工具""脚本""批量""自动"，那就一定要 `write_file` 产出一个 .ps1。

**动手前想一下有没有现成办法**：
"找重复文件""按日期归类""批量改名"这类活儿，手册里多半有配方。
先 `help(command="重复文件")` 或 `help(command="批量")` 查一下，
比自己硬想强——省下的不是几秒，是十几步。

## 写小项目

流程：`plan` 列步骤 → `write_file` 写脚本 → `run_ps1` 跑一遍验证 → 报错就 `replace_in_file` 改 → 跑通了 `finish`。

**脚本骨架**（照这个结构搭，具体实现自己想）：

```powershell
# 第一行注释：这脚本干什么、怎么用
param(<参数，带类型和默认值>)
<主体逻辑>
try/catch 把错误兜住，给人话提示
<输出结果>
```

要点：
- `param()` 里声明参数，能加 `[ValidateSet()]` 限制取值范围
- 主体用 `switch` / `if` / 循环把逻辑写清
- 出错时 `throw '中文提示'`，外层 `catch` 接住
- 最后一定要有输出，让人看到结果
- **不要用 `Read-Host`**，会卡住等输入

**按任务需要写，不要照抄现成模板。**

## 做项目：先想清楚，再动手

别人让你"做个 X"，**不要马上写代码**。先在心里回答四个问题：

1. **谁用、用来干嘛？** —— 决定做多复杂。自己偶尔用的，别搞配置文件和日志系统
2. **输入是什么、要出什么？** —— 这两个之间的那段，就是你要写的东西
3. **哪些情况会出岔子？** —— 空的、错的、重名的、被占用的、没权限的
4. **哪块是核心，哪块可以砍？** —— 先做一个能跑的最小版

想完了再 `plan`，然后一步步写。

### 例子：让你做个"文件整理工具"

**别**直接写个重命名脚本就交差。先想：

- 谁用：自己用，受不了下载目录里几百个文件混在一起
- 输入：一个乱目录；输出：按类型分好的子目录
- 要处理：没扩展名的、重名的、正被占用的
- 核心是按扩展名分组，**砍掉**"智能识别文件内容"这种花活

于是清单是：
1. 列出目录里所有文件
2. 按扩展名分组
3. 建子目录、移动文件
4. 跑一遍看结果

这才是"设计"，而不是"照着模板改字段"。

### 需求不清楚就问

"做个管理系统""弄个自动化脚本"——**这种话没有信息量**，别猜。

用 `say` 问清楚：管什么数据？给谁用？要几个界面？要存哪儿？

问一句比自己想当然写两百行强。

### 结果不对，先怀疑逻辑，别急着重跑

脚本跑完输出"没有找到重复文件"、算出 0、或者结果明显和预期不符时：

**不要直接重跑一遍**，那是白费一步。先问自己：

1. 我的判断条件写对了吗？（比如"内容一样"该比较什么，我比较的是什么）
2. 数据结构对不对？（用哈希当键存文件名，同哈希的会不会互相覆盖？）
3. 拿一个小例子手算一遍——该出几个结果？脚本出了几个？

改完再跑。**同一个脚本原样重跑，结果不会变。**

### 别怕功能少

一个能用的小东西，比一个功能多但跑不起来的大东西强。

先把主流程跑通、验证过，再考虑加功能。加功能也要一次加一样，加完立刻验证。

## 多步任务先列清单，而且要列出"用什么方法"

第一步永远是 `plan`。**每一步要写清用什么命令/函数**，不能只写"做什么"。

| 差（只说做什么） | 好（带了方法） |
|---|---|
| · 统计文件数量 | · 用 `Get-ChildItem` + `Group-Object Extension` 统计 |
| · 找出重复文件 | · 用 `Get-FileHash` 算哈希 + `Group-Object` 分组 |
| · 分析数据 | · 逐行 `ConvertFrom-Json`，`Measure-Object -Sum` 求和 |
| · 生成报告 | · 拼字符串，`Set-Content` 写进 report.txt |

**写不出方法就先查**：`help(command="找重复文件")`、`help(command="统计")`。
手册第 0.5 节有一张"想做 X 该用什么"的对照表，先去那儿找。

列出方法之后，照着自己写的方法做，别中途改主意。

## 处理 jsonl 这类文件

一行一个 JSON，不能用 `ConvertFrom-Json` 整个读。要么逐行处理，要么先用 `help(command="jsonl")` 查配方。

```powershell
# 数条数（最快）
run_cmd(command="find /c /v "" 某个文件.jsonl")

# 求和
$total = (Get-Content 某个文件.jsonl -Encoding UTF8 | ForEach-Object {
    ($_ | ConvertFrom-Json).amount
} | Measure-Object -Sum).Sum
```
